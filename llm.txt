ndim-lsp LLM handoff
====================

Purpose
-------
ndim-lsp is a Rust/tower-lsp + tree-sitter-python project for static tensor shape analysis in Python code. The library modules under `src/` carry the analysis logic. `src/main.rs` is the LSP server (diagnostics, hover, inlay hints, and for symbolic dims definition, references, highlights, and rename, plus safe matmul fixes) on top of `analyze_layer_shapes`. `ndim-lsp check <path>...` (`src/check.rs`) runs the same analysis without an editor.

JAX compatibility audit
-----------------------

`bench/jax_compat/README.md` records the 0.9.2 -> 0.11.1 public-export audit,
its eight namespaces, source links, and conservative limits. This covers
recent additions, not all older or experimental JAX APIs. `audit.py` can
repeat the export comparison for the next release without installing JAX.

`src/known_functions/jax.rs` adds rules for the 26 new array functions of
that audit. Only unpacking exposes the component shapes of top-k and
qr_multiply. Shape-changing options that are not static stay unknown.

`stack`, `concatenate`/`cat`, `vstack`, `hstack`, `dstack`, and `column_stack`
read each list/tuple element (including inline array expressions) as one
operand, in JAX, NumPy, and PyTorch. A list comprehension over a provable array
is expanded to N copies of one element (N from 1 to 256, else unknown). Any
other sequence (a variable `xs`, a generator) or an element with an unknown
shape makes the call unknown. `block` with a tuple literal is unknown (NumPy
and JAX reject it); einops `rearrange`/`reduce`/`repeat` with a tuple of
tensors are unknown. `einops.pack` reads raw arguments and handles tuples.
An einops pattern with more than one `...` on a side is unknown (einops rejects
it).

End-to-end LSP stress benchmark
-------------------------------

`bench/generate_stress.py` writes `bench/stress/` deterministically (fixed seed):
a 22,323-line `stress_main.py`, five imported helper modules, and a 500-line
`paste_block.txt`. Regenerate with `python3 bench/generate_stress.py`.
`tests/lsp_stress.rs` spawns the built `ndim-lsp` binary, talks JSON-RPC over
stdio, and runs about 40 scenarios (open, edits, bursts, typing, paste and
delete, inserted errors, helper-file edits, hover, definition, inlay requests,
a tiny document).

Markers in the generated Python define the expected result and come from
operation semantics, never from analyzer output:
`# expected-error:`, `# expected-shape: a=[b, 4]`, `# stress-site: <name>`.

The tests are `#[ignore]`:

```sh
NDIM_STRESS_RUNS=3 NDIM_BENCH_OUT=/tmp/bench.json cargo test --release --test lsp_stress lsp_stress_benchmark -- --ignored --nocapture
NDIM_GOLDEN_OUT=/tmp/golden.json cargo test --release --test lsp_stress golden_dump -- --ignored --nocapture
```

- `NDIM_STRESS_RUNS` (default 5) sets the runs per scenario.
- `NDIM_BENCH_OUT` writes the JSON result. `NDIM_GOLDEN_OUT` writes the golden dump.
- Latency is total = debounce + server compute (from the server's
  `analysis: total=Nms` log) + other (transport and scheduling). The debounce
  column is the `debounce=` field of the same log line.
- Peak RSS is sampled with `ps` every 25 ms, so it is a lower bound.
- The harness sends full text with no range, so it does not measure the saving
  of incremental sync transport.
- Do not benchmark with `NDIM_VERIFY_INCREMENTAL=1`: it adds a fresh parse and a
  fresh analysis to every edit.

Golden gate for refactors: `golden_dump` writes every diagnostic and inlay hint
of the stress project. Dump before and after a change, then `cmp` the two files.
A cleanup or a speed change must give a byte-identical dump. Do not fix
analyzer defects inside such a change, because the fix changes the dump.
`golden_has_no_internal_names` checks that no `__synth_`, `__ellipsis`,
`__free_`, or `__unproven` name reaches a message or a hint.

The harness checks about 13,800 expected markers (6,410 in `stress_main.py`,
6,637 in the paste payload, the rest in the helper modules). A `?` marker
(`# expected-shape: e=?`) says the name must have no shape: use it where
unknown is the true answer.

`lsp_stress_benchmark` asserts the markers and the scenario invariants. Do
not loosen the test to make it pass.

Incremental analysis
--------------------

An edit costs a reused parse and a replay of the unchanged parts. The result
must always equal a fresh analysis of the same text. Three layers:

1. Sync and parse (`src/sync.rs`, `src/incremental.rs`, `src/main.rs`).
   - The server advertises `TextDocumentSyncKind::INCREMENTAL`.
     `apply_changes` applies the ranged changes in order to the stored text
     (positions in the negotiated encoding; lines end at `\n`, `\r\n`, or
     `\r`). A change without a range replaces the whole text.
   - `diff_edit` finds the one edit between the old and the new text (common
     prefix and suffix). `reparse` feeds it to tree-sitter with the old tree.
     If the old tree or the new tree has a syntax error, `reparse` parses from
     scratch, because tree-sitter recovers differently from errors with a
     reused tree. So the tree always equals a fresh parse, also after errors.
   - `DocState.committed` (one `DocState` per open URI) keeps the text, tree,
     memo, and import reads of the last committed analysis. `commit` runs
     only for a successful result of the newest rev, so a stale or failed
     analysis changes nothing. A save or watched-file event gives new revs but
     keeps `committed` as the base: the memo checks its disk dependencies
     itself.
2. Pre-pass memo (`UnitMemo`, `analyze_layer_shapes_with_memo`).
   - A "unit" is a top-level statement (every root child; an anonymous `;`
     is also a unit with an empty record). The pre-passes (`PrePass`: scopes,
     annotations, layer assignments, self-attribute layers, class summaries)
     are stored per unit in unit-relative positions
     (`SyntaxRecord`, `LayerRecord`), and shifted to the new positions with the
     `Shift` trait, `Delta`, and `Remap`.
   - A unit with the same text reuses its `SyntaxRecord`. A `LayerRecord` also
     needs the same imports (`import_digest`, a digest of the file map, the
     module map, and the rebound names, so an edit of any import line
     recomputes the layer records of all units) and valid disk dependencies (`ResolutionCache::record_deps`,
     `deps_valid`). A `RegionRecord` holds the import regions of the unit
     (`ImportRegion`, unit-relative) and needs the same digest. `unit_digest`
     adds the names that are rebound above the unit. The places of a rebinding
     are not in the digest, so an edit above a rebinding reruns no unit. A layer record keeps the raw text of each dim, so that
     it does not depend on a constant of another unit. `ShapeCtx::layer_at`
     writes the values at each lookup.
   - A unit with a syntax error is never reused, because its parse can depend
     on the text after it.
   - The first analysis of a text builds no memo, so open stays fast. The
     first edit builds it and analyzes every unit (see the open trade-off in
     the stress section). A file over 4 MiB of text or 100,000 units gets no memo
     (`MAX_MEMO_TEXT`, `MAX_MEMO_UNITS`) and runs the plain path.
3. Propagation memo (`PropPlan`, `PropRecord`, `src/incremental/names.rs`).
   - `names.rs` finds the names each unit defines and reads and links units that
     share a name (a union-find over name hashes). The closure over-approximates:
     every identifier token counts as a read. Common names such as `__init__`
     and `forward` join most units into one hub group (567 of 858 units on
     `stress_main.py`), so an edit in a hub saves only part of the cost.
   - The plan marks the groups with a changed unit as dirty. Dirty groups run
     the propagate pass (`run_units`); clean groups replay their stored output
     (`Segment`s of errors, applications, assignment shapes, and the final scope
     shapes), shifted to the new positions. Statement-level groups need a
     `Remap` that finds a unit for every position. Loop bodies replay as part
     of their unit.
   - The plan falls back to a full run (`propagate_full`) when the dirty bytes
     exceed `MAX_DIRTY_SHARE` (0.6) of the file, a position has no unit, or two
     statements share a row. A fallback run records too, so later edits can
     replay.
   - The setup of the pass (function nodes, scope links, submodules,
     `original_shapes`, `ScopeIndex`) still runs over the whole file on any
     dirty edit (about 14 ms). It is not incremental.
   - Each dependency that an analysis feature adds must be visible to this
  model. The name test for a new binding reads only the function, or at
  module level the linked identifiers plus a digest of the global names and
  wildcard imports. A function that reads a module global joins the group of
  the global through the shared/reads edge of `names.rs` (a reader mentions
  the name, and a module write, a class body write, and a `global` statement
  all join one group), so no new edge type exists. The environment hash also
  holds the clash set: the annotation symbols that a unit assigns as an integer
  or reads. Add or remove such a symbol, and every group runs again, because
  `integer_constant` and `layer_at` treat the name differently (in `layer_at`
  a parameter wins over an annotation). The environment hash also holds
  whether the root of the tree is an `ERROR` node, which tree-sitter gives
  when it gives up on a whole file. Such a root is no `module`, so
  `nearest_binding` and `module_global` read the module scope differently for
  every unit, and a change of the root kind reruns all units. `flow::visit`
  enters an `ERROR` root like a `module`, so the whole-tree pass and the
  per-unit pass see the same branches. A `vmap` assignment has no edge of
  its own: a reader mentions the name, and `vmap_target` reads only the scope
  that owns it. A file that binds a tracked name again changes the
  `Rebound` list, so the first rebinding of a name reruns all units. Module
  classes of other files record a probe dependency (`Deps` per probe, class
  source cache), and in-place changes of a field are found by name in the
  whole file. Comprehension and lambda bodies run inside their unit, and
  `sum`, `range`, `len` resolve through the unit's definitions, imports, and
  wildcard imports.
- `NDIM_NO_PROPAGATE_MEMO=1` is a kill switch: it turns layer 3 off and runs
     the whole-tree propagate pass (the pre-pass memo stays on).

`ResolutionCache` supports the memo with a per-path generation (a count of
`revalidate` marks; `clear` empties the generations, and the clear count
makes every older `Deps` invalid) and a cache id. `record_deps` records
which files a computation touched and `deps_valid` tells if they are unchanged.
A save that keeps mtime and size is seen only through the editor event path
(`revalidate` with the changed path). An editor buffer change goes through
`ResolutionCache::buffer_changed` (see "Known limitations").

Verify mode. `NDIM_VERIFY_INCREMENTAL=1` (server environment) makes each edit
that has a base also do a fresh parse and a fresh analysis and compare them
(`first_tree_difference`, `first_analysis_difference`). On a difference the
server logs `incremental mismatch, used the fresh result: ...`, uses the fresh
result, and drops the memo. In `cfg!(test)` builds the same difference panics.
The cost is one extra fresh parse and analysis per edit, so never time with it.

Tests: `src/incremental_tests.rs` and
`tests/incremental_edits.rs` (seeded random edit sequences over `corpus/` and
`bench/stress/`; after every edit the reparsed tree and the memo analysis must
equal the fresh ones; seeded edits also change each added dependency, such as
a module global and its write order, a branch name, a lambda helper, and an
imported module class). The ignored
`stress_main_two_thousand_chained_edits` runs 2,000 chained edits of the stress
file in release (`NDIM_CHAIN_STEPS`, `NDIM_CHAIN_SEED`, `NDIM_CHAIN_TIMES`).

Debounce and sync mode
----------------------

- `DEBOUNCE` in `src/main.rs` (150 ms) is the longest quiet time before a
  change is analyzed. `Pace` (`src/sync.rs`) keeps, per document, the time of
  the last change and a moving average (EWMA, alpha 0.5) of the wall time of
  recent analyses.
- The debounce is a function of the cost only (`Pace::debounce`). After an
  incremental run a change waits `0.5 x average`; after a whole analysis it
  waits `2 x last cost`. The result is clamped to 20 through 150 ms. A
  document with no known cost waits 150 ms. `didOpen` does not wait.
- The first incremental run replaces the cost of a whole analysis (no averaging
  with it). A whole analysis replaces the average. A failed run clears it. Every
  re-analysis of the open documents (a root change, or a save or watched file
  event that dropped cache entries) clears it too, and the runs up to that
  forced rev give no sample (`Pace::reset`). The next edit then waits 150 ms.
- A run that a newer key replaced still gives a sample (`Pace::sampled`), so
  a costly run raises the debounce during typing, and analyses cannot pile
  up. The gate runs one analysis at a time for each URI. On a file with a very
  long analysis, steady typing can keep one core busy, and no result is
  published until the typing stops.
- A buffer change of an imported file (`buffer_changed`) keeps the cost of the
  dependent documents: their run costs what an edit costs.
- The first call after a change waits out the debounce of its rev. Hover, inlay,
  and other requests share that one analysis (single-flight per uri and rev,
  one analysis at a time per URI).
- Sync is INCREMENTAL. A position past the end of a line or of the text clamps to
  that end, as the LSP spec says. A position inside a char (a surrogate pair
  in UTF-16, a multi-byte char in UTF-8), or a range that does not fit the stored
  text, drops the whole message and keeps the old text: the later changes are not applied to a text
  the editor does not have. The document is then out of sync (`in_sync` is
  false): it gets no analysis until a message with a full text arrives. The
  server publishes no diagnostics for it and answers inlay requests with null,
  and logs a warning. A stale version (older than the stored one) is ignored.

Limits of the incremental path
------------------------------

- Hub edits (`edit_init_layer`, `paste_500_lines`) save only part of the cost.
- The first edit after open (`edit_char_start`) analyzes every unit, because
  open builds no memo.
- Units with a syntax error are not reused.
- Module-global reads use the shared/reads edge, which over-approximates
  (every identifier token is a read), so a comprehension target joins the
  group of an equal global name. That costs reuse, never correctness.
- Replay clones the segments and the final scope shapes for the output. A clean
  group whose units did not move is shared by reference.

Rule for agents working on this repo
------------------------------------

**Verify before implementing.** `src/` is the source of truth; the roadmaps are summaries and may lag it. Before adding a known function, layer, or analysis feature, grep first:

```sh
grep -E "KnownFunction::|apply_known_" src/known_functions.rs
grep -E "LayerKind::|\"<ClassName>\"" src/layers.rs
grep -n "<feature_name>" src/analysis.rs src/main.rs
```

If the feature already exists, **stop and report that finding**. Do not add adjacent work or duplicate tests to justify the run. If the existing tests already cover the cases of the task, the task is done.

Current file layout
-------------------

- `src/lib.rs`
  - Small public facade with an explicit export list:
    `analyze_layer_shapes`, `analyze_layer_shapes_with_memo`, `UnitMemo`,
    `reparse`, `first_tree_difference`, `first_analysis_difference`,
    `ResolutionCache`, `new_resolution_cache`, `clear_resolution_cache`,
    `with_document`, and the types `FunctionShapeScope`, `LayerShapeAnalysis`,
    `ShapeError`, `ShapeErrorKind`, `ShapeFix`, `scope_for_byte`. Tests see
    every module through a `#[cfg(test)]` glob re-export.

- `src/types.rs`
  - Shared public data types/enums.
  - Important types:
    - `ImportPath`
    - `CallInfo`
    - `ResolvedTarget`
    - `ResolvedModuleTarget`
    - `PythonSymbol`
    - `ResolvedImplementation`
    - `PythonCallableSignature`
    - `CallArgument`
    - `ResolvedCallSignature`
    - `LayerKind`
    - `KnownFunction`
    - `LayerApplication`
    - `ShapeError` / `ShapeErrorKind` / `ShapeFix` — diagnostics, confidence,
      related location, and optional editor fix metadata. `reads` (the names
      the source of the error reads, for the filters) and `named` (the
      statement gave `variable`) are not part of equality.
    - `dims_conflict`, `names_conflict`, `Conflicts`, `NAMES_ONLY` — which
      conflict is a `Mismatch` and which an `Approximation` (item 18b)
    - `ShapeDimensionSite` — exact source range for one annotation dimension
    - `FunctionShapeScope` (function-scoped shape map plus `dimension_sites`)
    - `AssignmentShape` (`line`, `name`, `shape`) — per-assignment record for inlay hints
    - `LayerShapeAnalysis` (`scopes`, `layers`, `applications`, `errors`, `assignment_shapes`)
    - `ScopeIndex` — byte-to-scope lookup over nested or disjoint scope ranges,
      built once per propagate pass (the old linear `scope_index_for_byte`
      scan stays for other range sets)
  - Public helpers: `scope_for_byte`, `scope_index_for_byte`.
  - (`CoverageReport` / `DarkSpot` live in `src/analysis.rs`.)

- `src/main.rs`
  - tower-lsp server binary: options, diagnostics, hover, inlay hints,
    definition, references, document highlights, rename and prepareRename of
    dims, code actions, workspace folders, site-packages and `src` layout roots.
  - All state of one open document is one `DocState` (`doc`, `committed`,
    `gate`, `pace`) in `Backend.documents`.
  - Incremental flow: `change_document` applies a change message,
    `run_analysis` takes the base from `DocState.committed` and the open
    buffers (`Buffers`), `compute_analysis` / `analyze_text` reparse and
    analyze (with the optional `NDIM_VERIFY_INCREMENTAL=1` check), `commit`
    stores the result for the newest rev only. A panic in the analysis task is
    logged (`analysis panicked`). See "Incremental analysis".

- `src/sync.rs` (a module of the binary)
  - `Pace` (adaptive debounce and the analysis-cost average), `apply_changes`
    (ranged changes to text), `Encoding` (UTF-8 or UTF-16), and `LineIndex`:
    the line starts of one text under the LSP line model (`\n`, `\r\n`, `\r`),
    so a position conversion scans one line. A tree-sitter row ends at `\n`
    only, so `row_lines` maps a row to its LSP lines.

- `src/check.rs` (a module of the binary)
  - `ndim-lsp check [--shapes] <path>...`. Prints `path:line:col: error|warning:
    message`, one line per diagnostic, and with `--shapes` also
    `path:line: name: [dims]` per assignment. Files run in sorted path order. A
    directory walk skips hidden directories and `.venv`, `venv`,
    `node_modules`, `build`, `dist`, `__pycache__`, `site-packages`. The search
    roots are the current directory (plus its `src` layout root) and its
    site-packages. Exit code 1 for at least one `Mismatch`, 2 for a usage,
    read, or analysis error, else 0 (warnings do not change it). The summary
    `N files, E errors, W warnings` goes to stderr.

- `src/incremental.rs`, `src/incremental/names.rs`
  - Incremental parse (`diff_edit`, `reparse`), the pre-pass memo (`UnitMemo`,
    `PrePass`, `SyntaxRecord`, `LayerRecord`), position shifting (`Shift`,
    `Delta`, `Remap`), the propagation plan (`PropPlan`, `PropRecord`,
    `Segment`), and the equality checks (`first_tree_difference`,
    `first_analysis_difference`). `names.rs` has the per-unit name sets and the
    union-find that links units.
  - Re-exported from `src/lib.rs`.

- `src/incremental_tests.rs`
  - Library tests for the above.

- `src/analysis/flow.rs`
  - Control flow: branch merge for `if`/`elif`/`else`, `match`, `try`, loops,
    and `with`. Each arm starts from the entry state; the live paths join.
- `src/analysis/inner.rs`
  - `Frame` model for lambda and comprehension bodies.
- `src/analysis/layer_dims.rs`
  - The values of the names in the dims of a layer constructor (`layer_at`,
    `argument_value`), the free mark on the size arguments of a call
    (`with_free_argument_dims`), and the size of a slice (`slice_size`).
    See item 18b.
- `src/analysis/modules.rs`
  - Module fields (`ModuleList`, `Sequential`, lists, comprehensions, chain
    loops, indexing), module probes for classes of other files, and loss
    layers (`LayerKind::Loss`, `LayerApplication.extra_inputs`).

- `src/imports.rs`
  - What an imported name means at a place of the file. `ImportScopes` holds
    the module map, the file map (`file()`, for the file-wide backend), the
    `ImportRegion` list, and the `Rebound` list. `ImportScopes::at(byte)` gives
    the map of a place. Function bodies, lambdas, and comprehensions that
    change a name get a region. See item 22.

- `src/known_functions/jax.rs`
  - `classify` and shape rules for the JAX 0.10/0.11 additions.

- `src/jax_compat_tests.rs`
  - Analyzer tests over the `bench/jax_compat/` fixtures.

- `src/python_ast.rs`
  - Pure tree-sitter Python extraction helpers.
  - Important functions:
    - `build_import_map` (scopes: `src/imports.rs`), `module_binds`
      (`ModuleBind`: the place, `hides_class`, `hides_import`)
    - `extract_calls`
    - `extract_call_arguments`

What works now
--------------

1. Python import parsing
   - Supports plain imports, aliases, dotted imports, from-imports, relative imports, parenthesized/multiline imports, duplicate import last-wins.
   - `import a.b.c` binds `a` to the top package, as Python does.
   - Star imports are skipped.

2. Assigned call extraction (`extract_calls`): `layer = eqx.nn.Linear(...)`
   and `y = layer(x)`; tuple unpacking, attribute targets, and bare calls are
   skipped.

3. Import/call target resolution
   - `resolve_call_target` combines call target text with an import map from
     `imports.at(byte)` (item 22): with `import equinox as eqx`,
     `eqx.nn.Linear` -> `ResolvedTarget { parts: ["equinox", "nn", "Linear"] }`.
     The relative dot count stays in `ResolvedTarget`.

4. Module resolution on disk (`resolve_target_probing`)
   - Checks `root/foo/bar/__init__.py`, then `root/foo/bar.py`: a package
     directory wins over a module file. No filesystem crawling.
   - As `sys.path`: the first root with the top-level package or module owns
     it and its submodules. A namespace package (no `__init__.py`) has no
     owner, so every root is searched.
   - A package whose `__init__.py` binds a submodule name to anything but that
     submodule gives no module (`submodule_unshadowed`).
   - The server and `check` add `<root>/src` as a root when it exists and is
     no package itself (`with_src_layout`).
   - A relative import of the open document resolves next to its file
     (`with_document`). A re-export hop resolves relative to the package of
     the importing file (`package_of`: the module itself for an
     `__init__.py`, else its parent).

5. Symbol/re-export following
   - `find_top_level_symbol` detects top-level class/function/import. A name
     that the module binds more than once gives no symbol (`bound_once`),
     also when Python would use the last binding. Two straight-line `def`s,
     an `@overload` set, a repeated import, and `import a.b` plus `import a.c`
     all count. A `global` statement for the name, or a wildcard import after
     the binding, also gives no symbol. A wildcard import before the binding
     has no effect. `del`, `case`, and `type` statements count when they
     mention the name, so `del table[proj]` gives unknown too. The module
     walk does not enter function bodies, and the `global` scan runs only if
     the text contains that word.
   - `resolve_implementation` follows import re-exports until class/function
     found, with max depth and cycle detection. A re-export rebound in its
     module gives no symbol, so the walk stops. A decorated top-level
     definition counts (decorators are ignored).
   - The analysis does not see dynamic rebinding: `globals()["f"] = g`,
     `setattr(module, ...)`, or `lib.f = g` from another file.

6. Callable signatures and call bindings
   - `extract_callable_signature` extracts:
     - top-level function params
     - class `__init__` params
   - `extract_call_arguments` gets positional/keyword call args.
   - `bind_call_arguments` maps args to param names and skips `self`/`cls` for class constructors.
   - Same-file and cross-file binding follow Python: a parameter after `*` or
     `*args` takes a keyword only, one before `/` a position only, and a splat
     in the call (`*xs`, `**kw`) binds nothing from it on.

7. Jaxtyping shape annotation extraction
   - `extract_jaxtyping_shapes` extracts function parameter shape strings like:
     - `x: Float[Array, "batch features"]`
   - Handles common wrappers and qualified `Array` forms.
   - Rejects f-strings/bytes strings and non-array string annotations.
   - Returns `Vec<FunctionShapeScope>`: index 0 is a module scope spanning the whole file, followed by one scope per `function_definition` (DFS order), each with its own `shapes` map. `scope_for_byte` picks the smallest scope (a size tie goes to the inner one).

8. Equinox Linear layer flow
   - Resolves and classifies `equinox.nn.Linear` through imports/re-exports.
   - Extracts layer assignments:
     - `layer = eqx.nn.Linear(3, 5)` -> `layer -> LayerKind::Linear { in_features: "3", out_features: "5" }`
   - The propagate pass applies a layer at its call (`y = layer(x)`).
   - Applies layer shape rules:
     - input last dim must match `in_features`
     - output last dim becomes `out_features`
   - `analyze_layer_shapes` orchestrates annotation extraction + layer extraction + propagation.

9. Known built-in function classification
   - `classify_known_function` recognizes many JAX NumPy, NumPy, Torch, and JAX LAX functions (see `KnownFunction` and `TO_IMPLEMENT.md`).

10. Known built-in shape rules already implemented
   - `concatenate` / `cat`
   - `stack`
   - reductions: `sum`, `mean`, `max`, `min`, `prod`, `std`, `var`, plus `all`, `any`, `argmax`, `argmin`.
     `KnownFunction::Reduction { axis, keepdims, q }` reads the positional
     slots of each library signature, so a positional `keepdim` works: torch
     `(input, dim, keepdim)` (`std`/`var` with `unbiased` before `keepdim`),
     numpy `(a, axis, dtype, out, keepdims)`, `median`, `quantile` and
     `percentile` (the shape of `q` leads the result), `norm(x, ord, axis,
     keepdims)` (`NORM`, also `x.norm(p, dim, keepdim)`), `logsumexp`
     (`return_sign` gives unknown), `count_nonzero` (`keepdims` by keyword).
     A method reads the torch signature in a torch-only file
     (`torch_method_reading`, the same per-file backend as `x.transpose`);
     `repeat` and `squeeze` follow it too (torch `x.repeat(*sizes)` tiles, and
     torch `squeeze` keeps a dim that is not 1, where numpy and jax report an
     error).
   - `reshape`
   - `flatten`, `ravel`
   - `transpose`, `swapaxes`, `moveaxis`, `permute`
   - `expand_dims`, `squeeze`, `atleast_1d`, `atleast_2d`, `atleast_3d`
   - `broadcast_to`, `broadcast_arrays` / `broadcast_tensors`
   - `tile`, `repeat`
   - shape-preserving: `roll`, `flip`, `triu`, `tril`, `argsort`, `sort`, `cumsum`, `cumprod`, `array`, `asarray`, `*_like`
   - elementwise functions (`is_shape_preserving_call`): the one-operand ones
     (`exp`, `sqrt`, `abs`, `tanh`, ...) keep the shape. The two-operand ones
     (`maximum`, `minimum`, `fmax`, `fmin`, `add`, `multiply`, `power`,
     `arctan2`, `hypot`, `copysign`, the comparisons and logical functions in
     numpy, jax and torch: `torch.add`, `sub`, `mul`, `div`, `pow`, ...)
     broadcast both operands, and a Python scalar broadcasts against anything.
     A mismatch, a third positional argument, or an operand passed by keyword
     gives unknown. `torch.max` and `torch.min` have their own rule.
   - `clip` / `clamp` (`KnownFunction::Clamp`, free and method form): the input
     broadcasts with every array bound, so a larger `min` or `max` array makes
     the result larger. Bounds that are `None` or provable scalars are removed
     first. A bound with no known shape, or a mismatch, gives unknown.
   - `torch.bmm`: both operands rank 3, equal batch dim (a batch of 1 does not
     broadcast), equal contracted dim; result `[b, n, p]`.
   - `F.cross_entropy` / `F.nll_loss`: the class dim is axis 0 for an
     unbatched input and axis 1 otherwise. A target of the input's shape holds
     probabilities (`cross_entropy` only), a target without the class dim holds
     class indices. `reduction='none'` gives the input shape without the class
     dim, any other valid reduction a scalar. A `weight` must be rank 1 with
     one entry per class.
   - `where`
   - constructors: `zeros`, `ones`, `full`, `empty`, `arange`, `linspace`, `logspace`, `eye`, `identity`
   - diagonal/indexing basics: `diag`, `diagonal`, `trace`, `take`
   - linear algebra basics: `matmul`, `dot`, `jax.lax.dot`, and an exact
     `jax.lax.dot_general` (literal `dimension_numbers`: batch dims, then the
     free dims of `lhs`, then of `rhs`; any other value is unknown);
     `torch.mm`, `mv`, `addmm`, `baddbmm`, `x.t()`, `F.linear`,
     `F.scaled_dot_product_attention`, linalg `eigvals`, `matrix_power`,
     `multi_dot`, `slogdet`
   - functional losses (`F.mse_loss`, `l1_loss`, `smooth_l1_loss`,
     `huber_loss`, `binary_cross_entropy`, `..._with_logits`) use the rule of
     the loss layer (`FunctionalLoss`)
   - data-dependent sizes: `unique` (plain call), `masked_select`, `extract`,
     `compress` (no axis), and `bincount` give `[?]`
   - a call that returns a tuple for an option gives unknown for one name:
     `linspace(retstep=True)`, `indices(sparse=True)`, `histogram`,
     torch `sort`, `max_pool(return_indices=True)`, `unique(return_counts=...)`
   - stacking family: `vstack`, `hstack`, `dstack`, `column_stack`, `row_stack`
   - `pad`: numpy/jax pad widths in axis order; `F.pad` (`TorchPad`) pairs for
     the last dims, the last dim first
   - einsum: NumPy, torch and JAX skip spaces in the subscripts (each other
     subscript is one letter); `einops.einsum` reads space-separated names
   - split, chunk, and array_split give no shape past `MAX_PIECES` (256)
   - integer arithmetic of the rules is checked; an overflow gives unknown
   - `rot90`

11. Recursive shape evaluator
   - `shape_of_expression` walks an assignment RHS bottom-up: `call`,
     `attribute`, `identifier`, `unary_operator`, `subscript`,
     `parenthesized_expression`, `binary_operator`, `tuple` (a shape only
     when all elements have the same shape), so chained calls propagate.

12. `self.<field>` attribute access
   - Class fields with jaxtyping annotations (e.g.
     `A_log: Float[Array, "d_inner d_state"]`) are extracted into module
     scope; `shape_of_attribute` resolves `self.A_log`, including through
     chained methods like `self.A_log.astype(jnp.float32)`. A module-level
     write of the same name makes `self.<name>` unknown.

13. Tuple-pattern unpacking
   - `a, b = jnp.split(x, ...)` binds per-element shapes via
     `compute_split_shapes`; `L, _ = x.shape` binds each dim as a zero-rank
     scalar (`_` skipped). Handled in source order, interleaved with single
     assignments, by `handle_tuple_assignment` / `tuple_rhs_shapes`.
   - Tuple-literal right sides (`a, b = x, y`, `(a, b) = ...`, `[a, b] = ...`)
     bind element by element (`tuple_literal_shapes`). Every element is
     evaluated before any target is written, so `a, b = b, a` swaps and a
     rotation of three names works. A starred target (`first, *rest = ...`)
     takes its position; the starred name is always unknown (Python binds a
     list). A duplicate target keeps the last element. Differing lengths, a
     splat on the right, or two stars make every target unknown and evict
     stale bindings. An element error is reported once.
   - Unpacking a name (`a, b = x`) has two meanings. An array unpacks into its
     rows: a literal leading dim must equal the target count (else unknown), a
     symbolic leading dim is accepted, and each target gets the shape without
     the leading dim. A tuple carry (a
     `lax.scan` init tuple, a tuple literal bound to a name, a seeded carry
     parameter such as `final_mean, final_var = final_carry`) gives each
     target the one shared element shape, because only homogeneous carries are
     tracked. The analyzer tells them apart: `tuple_carries` holds the names
     whose current binding is a tuple carry, and any other name counts as an
     array only when `name_is_array` proves it (a non-scalar shape annotation,
     or every assignment to it in its scope is an array expression). A name
     that cannot be told apart gives unknown targets. Never guess a row shape
     for a tuple. A tuple carry is no array: `resolve_shape` gives it no
     shape, and it has no inlay hint and no hover.
   - Augmented assignment (`x += y`): a shaped right side checks and records
     the broadcast result, a provable scalar keeps the shape, and any other
     right side evicts the binding (torch and numpy keep the shape in place,
     a jax array rebinds).
   - Control flow (`src/analysis/flow.rs`): `if`/`elif`/`else`, `match`,
     `try`, loops, and `with` run each arm from a snapshot of the entry state
     and join the live paths. A name with one shape on every live path keeps
     it, any other name is unknown. A name a loop body both reads and writes
     keeps its shape after the loop only if one pass leaves it unchanged
     (`x = f(x)`); otherwise it and every name written from it are unknown,
     and hints of the first iteration are taken back. Loop, `with`, and
     `except` targets, walrus names, `case` captures, `del`, `def`, `class`,
     and imports are binding events. Context managers that swallow errors
     are found by name (import aliases and the last name segment). Module
     scope does not count a `def` or `class` name as an earlier binding.
     Open: value statements (`return`, `assert`, bare calls) read the state
     at the end of the scope; literal conditions are not folded. Hover shows
     the shape of the assignment that holds at the cursor (see "Known
     limitations"). `vmap_targets` holds every `name = vmap(...)`
     per name, and `ShapeCtx::vmap_target` picks the call (item 18a).

14. Layer calls
   - `self.fc(x)` applies the layer of `self.<attr>` directly;
     `jax.vmap(self.layer)(x)` and `jax.vmap(f)(x)` apply it batched over the
     leading axis (`apply_vmap_call`).
   - `Linear(d, 3*d)` then `split(qkv, 3)` cancels the literal factor, so each
     chunk is `d` (`cancel_product_factor`).

15. Inlay hints
   - `LayerShapeAnalysis.assignment_shapes` records the shape at each
     (non-annotated) assignment line, so a reassigned variable shows a hint
     per line. `assignment_line` maps a tree-sitter row to the LSP line of
     the target.

16. Session-lifetime import-resolution cache
   - `ResolutionCache` keyed on `(import-path-segments, roots-fingerprint)` is
     shared across `analyze_layer_shapes` calls. Caches `ResolvedImplementation`
     in `map`, the extracted cross-file helper `FunctionShapeScope`s in
     `signatures`, and parsed trees in `parsed` (keyed by file text; `parses`
     counts real parses). Entries carry file stamps, failed lookups are cached,
     a changed file drops its entries, and the cache revalidates once per
     analysis (epoch).
   - `callables` caches the parameters of each class or function per (file,
     symbol). `parsed` (128 files), module probes (512), and handled editor
     events (4,096) are bounded: a full map is emptied.
   - For the memo each path has a generation (a count of `revalidate` marks;
     `clear` empties them), the cache has a clear count and an id, and
     `record_deps` / `deps_valid` tell if the files a computation touched are
     unchanged (see "Incremental analysis").

17. Closures read enclosing variables at call time
   - A closure that reads a variable of its enclosing function sees the shape
     the variable has when the closure is called, as Python does, not the shape
     at the definition. The body is evaluated at its own call, from inside the
     enclosing function or from another closure being evaluated there. Outside
     that, enclosing variables stay unknown (the whole-file pass evaluates a
     closure body at its definition).
   - Scope facts (`ScopeLinks`, lexical links between function scopes) cover only closures and
     the functions that enclose them. A name the closure binds itself
     (parameter, assignment, loop or `with` target, import, nested `def`,
     `global`) is local and shadows the enclosing one. A name that a nested
     closure or a method in the function rebinds with `nonlocal` is unknown. A call outside the enclosing
     function and a method closure through a class do not see function locals.
     A function reads a module global or integer constant when all writes come
     before the top-level statement of the reader and have one shape (a
     global that a class body also binds is unknown; constants must be one
     decimal literal or int-annotated; a function above the constant stays
     unknown). Integer constants resolve to the integer in call dims and in
     layer constructor dims (item 18b). Comprehension and lambda bodies read the live shapes of the scope where
     they stand (see item 21). Fully annotated closures read
     the call-time value too, and a mismatch with it is a true error, reported
     once.

18. User submodules (`self.<attr> = Block(...)`)
   - A field built from a class of the same file is a user module. Calling it
     (`self.blk(x)`, `Block(features=64)(x)`, `jax.vmap(self.blk)(x)`) runs
     the module's `__call__` (it wins) or `forward`, found through the class
     MRO, on the argument shapes. The constructor arguments give the
     `self.<attr>` fields and the parameters of `__init__` (or dataclass-style
     fields) their values, so two call sites of one class get their own shapes.
     A proven constant argument gives its value. An argument that the file does
     not prove gives unknown for an output that reads it (`P(cfg.hidden)(x)`).
     A vmapped module peels and restores the batch dim.
   - It stays unknown when the field is written with anything but one
     constructor call of one class of the file, when a class between the field
     and the method rebinds a field the method reads, when a base before the
     method is unresolved, and past the depth bound (recursion terminates).
     A same-named function never replaces an unresolved field.
   - Classes imported from other files run through a probe (depth 2, never
     for site-packages or library roots). Constructor arguments reach it only
     as literals, plain names, or simple arithmetic. A proven value reaches the
     probe as that value, and a name with no proven value becomes a parameter
     of the probe. Errors show at the call.
     Fields that are `nn.ModuleList`, `nn.Sequential`, a list of modules, or a
     comprehension of modules, indexing, and chain loops (`x = layer(x)` as
     the only body statement) are tracked; a repeat count that is not literal
     is known only if one application keeps the input shape. Any in-place
     change of a field (by attribute name in the file) makes it unknown, so
     `self.layers.append(...)` in a loop stays unknown. Modules in locals,
     `zip`, `reversed`, slices, and `ModuleDict` stay unknown. A class defined
     twice in one namespace makes its calls unknown. Loss layers (`MSELoss`,
     `L1Loss`, `SmoothL1Loss`, `HuberLoss`, `BCELoss`, `BCEWithLogitsLoss`,
     `CrossEntropyLoss`, `NLLLoss`) check input and target and apply the
     reduction; `weight` and similar options are not read.
   - Annotated callee parameters are checked against the argument shapes: a
     rank mismatch or two different integers are a `Mismatch`; a conflict that
     rests on a name is an `Approximation` (item 18b); a variadic annotation
     is no error. A name of a callee annotation that no argument binds (and
     that is no field of the instance) is free in the caller, so it claims
     nothing there. An error in the `return` of a specialized callee is
     reported once.
   - A layer call that gives a tuple (torch `RNN`, `LSTM`, `GRU`,
     `MultiheadAttention`, an `LSTMCell` of torch or equinox) checks the input
     but binds no shape to one name. `out = self.lstm(x)[0]` and `[1]` pick an
     element, and tuple unpacking binds the parts, also for a local layer
     (not only `self.<attr>`). Equinox `MultiheadAttention` and the other
     cells give one array.
   - A name that a module statement binds (`P = load()`, `import`, `with ... as`,
     a walrus, `del`, `case`, `type`, or a statement under `global P` in a
     function or a class: `module_binds`, which over-counts on purpose for
     classes) is not a class of the file, so a base with that name is opaque.

18a. Method calls (`ShapeCtx::method_callee`)
   - `self.m(x)`, `cls.m(x)`, and `super().m(x)` resolve through the MRO of the
     class of the method that holds the call. The result is one method of one
     class, never the smallest scope of that name. `super()` starts after the
     class of the call. `super(C, self)` needs the class of the call and the
     first parameter of the method.
   - An override in a subclass or a mixin of the file gives unknown at
     `self.m(x)` in the base class, also with a return annotation. A subclass in
     another file is not visible. An opaque base before the known base gives
     unknown.
   - It is unknown when: the first parameter of the caller is not `self` or
     `cls`; the name is a property or a field; the caller is a staticmethod or
     a free function with a parameter named `self`; `cls.m()` reaches an
     instance method (the call shifts the arguments); the method is defined
     twice; the call is recursive; or a scope rebinds the receiver
     (`receiver_holds`). Decorators other than staticmethod, classmethod, and
     the property family are ignored, the same as for free functions.
   - A bare name (`find_callee_scope`) reaches the nearest closure or the module
     function, never a method, and a closure only inside its enclosing
     function. A recursive bare call is unknown. The result is also unknown
     when a place between the call and the function binds the name other than
     by `def` (`ScopeLinks::hiding`, `poisoned`). For a module function, the
     module scope counts as such a place. A class body that holds the call
     counts too, and so does a lambda or a comprehension around the call
     (`bound_in_expression`). `vmap(f)` resolves `f` at the vmap site with
     the same rules.
   - A rebinding `f = T(f)` in the scope of `def f` keeps the function when `T`
     keeps the signature (`only_wrapped`, `keeps_signature`): `jax.jit`,
     `jax.checkpoint`, `jax.remat`, `equinox.filter_jit`, each with keywords
     only after `f`, and `functools.partial(f)` with no bound argument. The
     import map at the statement must prove `T`. `bound_once` and
     `rebound_names` apply the same rule to an imported `f`. The memo sees it:
     the statement shares the name `f` with each reader, and the import digest
     holds the maps and the rebound names. A rebinding of a method
     (`m = jax.jit(m)` in a class, `self.m = jax.jit(self.m)`) stays unknown.
   - These rules cost shapes on purpose. Any other module rebinding such as
     `f = wrap(f)` makes `f` unknown in the full file, and so does a second
     binding through a try/except import. A function with `global f` that only
     reads `f` is unknown. A comprehension hides its name in its full range,
     also in the first iterable.
   - `vf = vmap(f)`: `vmap_target` gives the call only when the scope that owns
     `vf` binds it to this one call and to nothing else. The rule is
     flow-insensitive, so branches cannot give a wrong shape, and
     `vf = vmap(f); vf(x); vf = vmap(g); vf(x)` is unknown. A module-level `vf`
     is unknown in a file with a wildcard import and in a module-level class
     body, because `nearest_binding` is opaque there.
   - A callable parameter is not proven: `apply(g, xs)` stays unknown.
   - `equinox.filter_vmap` maps like `jax.vmap` but takes its options by
     keyword only. An option that the rule does not model (`axis_size`), a
     non-integer axis, or a splat gives unknown; `axis_name` and
     `spmd_axis_name` change no shape.
   - `vmap(self.helper)`, `lax.map(self.helper, xs)`, `lax.scan(self.step, ...)`,
     `A.helper(self, x)`, and `p, q = self.helper(x)` stay unknown. `super().__init__()`
     is not evaluated, because the result has no use.

18b. Layer constructor dims (`src/analysis/layer_dims.rs`)
   - A layer keeps the text of each dim, and `layer_at` writes the values at
     each lookup. Each name of a dim becomes one of four things:
     - Its integer, when the file proves one: every write gives the same
       literal and, at module level, every write stands before the top-level
       statement of the reader. So `OUT = 4` with `nn.Linear(8, OUT)` gives
       `[n, 4]`. Integer arithmetic folds (`2 * OUT`).
     - Itself with the `FREE_DIM` mark, for a parameter, a dataclass field, or a
       name with no binding. The caller gives the value, so the dim conflicts
       with nothing: `def __init__(self, d): nn.Linear(8, d)` gives `[n, d]`,
       and an add with `[n, 4]` gives `[n, 4]`. A parameter wins over an
       annotation of the same name.
     - Itself, for a name that an annotation uses as a dim, when it is no
       parameter or field and has no binding or one literal value. A conflict
       of this name with another name or with an integer is an
       `Approximation` (see "Diagnostic kinds" below).
     - `UNPROVEN_DIM` otherwise. The output of the layer is unknown, because
       the value can be any integer: `OUT = load()`, an imported name,
       `cfg.size`, `n = x.shape[0]`, or a constant below its reader.
   - `self.<attr>` uses every write in the class family, in any method and in
     class bodies, and all writes must agree. `self.a = self.b` is unproven. A
     write outside the class (`m.out = 9`) or in another file is not visible.
     `M.OUT` through the class name is unproven.
   - Diagnostic kinds (`src/types.rs`, `aefacf0`, `62e9ebd`). Only two
     different integers are a proven `Mismatch`. A conflict that rests on a
     name (name against name, or name against integer: `names_conflict`) can
     be equal at run time, so it is an `Approximation` (default severity
     WARNING) and gives no result shape. `Conflicts` holds such a conflict
     while a check runs, so a proven conflict after it still gives a
     `Mismatch`; the message gets the `NAMES_ONLY` mark, and
     `ShapeError::mismatch` turns a marked message into an `Approximation`.
     This applies to binary operators, matmul, concatenate/stack, broadcasts,
     einsum labels, vmap batch dims, and callee parameter checks.
   - Free dims (`src/types.rs`). Dims stay strings, so the mark is the text
     prefix `__free_`, the same method as `UNPROVEN_DIM`. `dims_conflict` is the
     test of every mismatch check, and a free dim conflicts with nothing.
     `dims_canonically_equal` ignores the mark. `unified_dim` gives the result:
     a free dim takes the value of the other side, a difference such as `n-1`
     takes an exact dim, `UNKNOWN_DIM` takes any other side, and two other
     different free dims give `UNPROVEN_DIM`. `shape_of_expression` and `apply_known_function` drop
     a shape with `UNPROVEN_DIM`, so `[n, d] + [n, e]` is unknown and a hover
     shows nothing. `record_binding` also refuses such a shape.
     `without_free_marks` writes `?` for it in the layer of an application. A free dim against an annotation symbol gives the symbol,
     which is wrong only if that symbol is 1 at run time.
   - `LayerShapeAnalysis::without_free_marks` removes the marks at the end of
     the analysis, so that only the analysis sees them. A new comparison of dims
     must use `dims_conflict`, because the mark has no effect otherwise. A user
     name that holds the text of a mark (`has_mark`) cannot be told apart from
     a mark, so it is unproven and enters no dim.
   - The rule is wider than constructors. `with_free_argument_dims` marks a dim
     of a known call that comes from a name in an argument, for example
     `n = load(); jnp.zeros((3, n))` or `torch.zeros(3, self.d)`. An attribute
     gets the mark also when the class writes one integer to it, because code
     outside the class can write another. `slice_size` gives the size of
     a slice. An integer axis with proven start, stop, and step gives the size
     of Python, with negative values and steps. A symbolic axis `n` with
     integer bounds gets a form (`symbolic_slice_len`), for `a`, `b` > 0:
     `[a:]` is `n-a`, `[:-b]` is `n-b`, `[a:-b]` is `n-a-b`, `[:b]` and `[-b:]`
     are `min(b, n)`, `[a:b]` is `min(b-a, n-a)`, `[-a:-b]` is `min(a-b, n-b)`,
     and an empty range is 0. A step `k` > 1 gives `ceil(s/k)` with the size
     `s` of the range, and `[::-k]` gives `ceil(n/k)`. The `n-a` forms assume
     an axis of at least that many items: a shorter axis has size 0. The `min`
     and `ceil` forms have the `FREE_DIM` mark. A form is written on the text of
     the axis, so that `x[1:][1:]` is `n-2` and a free axis stays free.
     Forms use only names (`is_named_size`). A slice of `_`, `_n`, `#n`, `*b`,
     `...`, or `n=4` gives `?`, and such a dim conflicts with nothing. A slice
     of `min(l, e)` is a slice of `e` with the limit in the bounds
     (`form_slice_len`): `x[:4][5:]` is 0, `x[:4][:2]` is `min(2, n)`, and
     `x[:4][1:]` is `min(3, n-1)`. On a `ceil` form or a compound `min` form,
     only `[:b]`, `[-b:]`, `[::k]`, and an empty range have a form. The other
     slices give `?`. `offset_dim` gives `?` for a `min` form below 0 at every
     size. After a variadic dim (`*b`, `...`) the axis of an index has no
     proven position, so `shape_of_subscript` gives no shape unless the slice
     keeps all items or an ellipsis covers the variadic dim: `x[..., 1:]` on
     `*b m` is `[*b, m-1]`, and `x[:, 1:]` is unknown.
   - Bounds of one analysis. `bounded_dim` (`types.rs`) makes a dim over
     `MAX_DIM_TEXT` (256 bytes), or a form that holds `UNKNOWN_DIM`, into
     `UNKNOWN_DIM`. `shape_of_expression`, `normalize_shape`, the layer rules,
     and the annotation parser apply it. `joined_dim` checks the length before
     it builds a sum or a product, and `substitute_dim`, `rebind_callee_dim`,
     and `dim_with_values` stop when the text passes the limit. A value over
     `MAX_RANK` (64) has no shape. Integer dims use checked arithmetic and an
     overflow gives `UNKNOWN_DIM`, also in each size rule of `src/layers.rs`.
     `MAX_STATEMENT_STEPS` (20,000) limits the `shape_of_expression` calls of
     one statement with the bodies it calls, per statement so that a unit gives
     the same result in an incremental run. `specialize_callee_call` also takes
     one step for each node of the callee (`descendant_count`), and a call with
     too few steps has no shape. The most that a statement of `bench/stress` or
     `corpus` uses is 133 steps.
     `MAX_EXPRESSION_DEPTH` (200) limits open calls and a chain of name
     checks (deeper is not proven). `too_deep` gives an empty
     analysis for a tree deeper than `MAX_SYNTAX_DEPTH` (1,000), and the memo
     path checks only the units that changed. `checked_name` keeps a memo of
     the name checks (scalar, integer, torch, array), so that a chain such as
     `b = a + a` is linear. `inner.rs` clears it, because a lambda changes what
     a name holds. `tests/dim_growth.rs` measures bytes with a counting
     allocator.
   - Variadic dims. A shape with `*b` or `...` has a rank that is only a lower
     bound. `ShapeCtx::report` drops an error whose source reads a value with a
     variadic dim (it tests `ShapeError.reads`, not the message), so that
     every rule is covered at one place. Three errors stay.
     A binary operator error on two annotations has the range of the
     annotations: broadcast and matmul align from the right and stop at a
     variadic dim. A layer error stays unless it is about the rank
     (`report_layer`), because a layer reads the input from its last axis. `aligned_axes` binds the dims of a call before and after
     the variadic dim. A variadic parameter over no axis or over many axes gives
     no return shape, and a named dim with no proven axis is `?`.
     `apply_known_concatenate` and `apply_known_stack` use `fixed_axis` and
     `stack_axis`: an axis that crosses the variadic dim gives no shape. Before
     that, `variadic_join_conflict` gives the errors that the dims prove: a rank
     under the lower bound of another input, or a conflict on an axis with no
     variadic dim between it and an end. `can_be_axis` skips a dim that can be
     the axis of a concatenate. `joins_variadic_shape` adds such an error past
     `ShapeCtx::report`.
     `[:n]` keeps the axis only when `n` is an annotation symbol that no scope
     binds, or an attribute that holds a parameter of that name and has no
     other write (`stop_is_axis`). An unproven bound or step, `[-a:b]`, and any
     other negative step give `UNKNOWN_DIM` (`__free_?`). The axis stays, the
     reader sees `?`, and the rank and the other axes stay known. A step of 0
     and a negative step on a proven torch tensor (`is_torch_value`) drop the
     whole shape, because Python and torch refuse them.
   - Two plain dims (one integer or one name) conflict when they differ. Any
     other form (`n-1`, `split(n, 4)`, `min(4, n)`, `n/2`, `2*n`) conflicts
     only with a flat sum of the same names and another integer, so only when
     the arithmetic proves it: `n-1` conflicts with `n` and `n-2`, but not with
     `5`, `m`, or `(n-1)*2`. Outer brackets do not change a comparison
     (`(n+1)` is `n+1`); the text of the dim stays as written. `canonicalize_dim` reads a
     subtraction as a term with a sign, so `n-1+1` equals `n`. A product or a
     division writes a sum in parentheses (`factor_text`): `n*(m-1)`.
     `substitute_dims` replaces a name inside a form, so a call gives `m-1`
     for `q-1`. Next to a `*`, a `/`, or a `%`, any compound value gets
     parentheses (`operand_text`): `q/r` with `r` = `t*u` gives `s/(t*u)`. A
     value that is not a name gives `?` inside a form.
   - A dim can hold a comma: `min(4, n)`. `split_top_level` splits a size
     argument only outside brackets, and `parse_shape_value` gives such a dim
     the `FREE_DIM` mark. `parse_ints` gives nothing for a literal with a name.
   - `parse_shape_value` reads a tuple, a list, or one size (`is_one_size`). A
     plain name inside a tuple stays one dim. A name that is the whole size
     (`jnp.zeros(s)`, `x.reshape(s)`, `torch.zeros(s)`) gives `[s]` only when
     the scope proves it an integer, the dims of the tuple or list that is its
     one binding, else unknown. Any other expression gives no shape: a call, a
     slice of `x.shape`, a starred item, a conditional, a generator, a
     comprehension, or a product of a tuple. `sequence_sum` reads a sum of
     tuples, lists, and `x.shape` to a real shape, so `jnp.zeros(x.shape + (3,))`
     is `[n, m, 3]`.
   - A name with a literal value, when an annotation also uses the word as a
     dim, gets `LITERAL_DIM`: `__free_D__is_64`. An annotation dim `D` is a
     size that the value of the name does not bind, so the dim equals both 64
     and the symbol `D`, and it conflicts only with another integer. The reader
     sees 64. Inside an expression (`D * 2`) the name gets only the free mark.
     The literal 1 stays an integer, because a dim of size 1 broadcasts.
     An expression of only such names and integers folds to one mark of its
     value (`fold_literal_marks`): `D + D` is `__free_D__is_128`, so it still
     equals an annotation and conflicts with another integer. A value below
     zero is unknown. A size rule folds the same way (`literal_mark`).
   - A `padding` that is one name gets `PADDING_NAME` at classification. A
     string is also a valid padding, so `layer_at` keeps the name only for an
     integer, a literal, or a parameter annotated `int`. Any other name gives
     `UNPROVEN_DIM`. An expression such as `k // 2` stays a formula.
   - The cost is lost errors. The class body is checked with `d` free, and only
     the result is specialized for a call site, so `M(5)` with `h + y` on
     `[n, 4]` gives no error. With `x: "n d"` and `__init__(self, d)`, the
     parameter does not tie to the annotation, so `self.l(x) + y` on `[n, 4]`
     gives no error.

19. Scalar operands in binary operations
   - A binary-op operand is a provable scalar (`2`, `math.sqrt(k)`, `len`,
     `float`, `int`, `x.shape[<integer>]`, a numpy or jax elementwise function
     of scalars, a name only ever bound to scalars, arithmetic on those, or a
     scalar-typed parameter) or an array with a resolved shape. A scalar
     broadcasts against any array. An operand that is neither stays unknown,
     because it could be an array that broadcasts. The check is flow-insensitive
     on purpose (`name_is_scalar`), so a reassignment in a loop or branch cannot
     make an earlier read wrong.

20. Internal names never reach the output
   - The evaluator binds inline operands to synthetic names (`__synth_N`, text
     kept in `synthetic_text`) and uses `__ellipsis` internally. A shape with a
     dimension that holds an internal name is not stored. In error messages
     `scrub_internal_names` puts the source text back; an error whose message
     cannot be restored is dropped, because a garbled message is worse than
     none. Names unpacked from `x.shape` (`a, b, c = x.shape`) stand for their
     dims (`scalar_dims`), so `reshape(a * b, c)` shows real dims, and the
     name stops standing for a dim when it is rebound.
   - `golden_has_no_internal_names` and `internal_name_scan_detects_a_leak` in
     `tests/lsp_stress.rs` check the rule over the stress project.

21. Comprehensions and lambdas (`src/analysis/inner.rs`)
   - A body is evaluated once, where its result is used: a list comprehension
     in `stack`/`concatenate`, `sum` over a comprehension or generator, a
     lambda given to `vmap`, `lax.map`, or `lax.scan`, and a direct lambda
     call. The `Frame` binds the loop variable or parameter to the shapes of
     one iteration. Iterating needs a provable array. A dim spelled with the
     loop variable becomes unknown. A scan lambda with a tuple carry binds it
     unknown. Names a body binds are masked, so an outer name never leaks in.
   - Not evaluated: `ys = [f(x) for x in xs]` kept in a name, a lambda stored
     in a name, set and dict comprehensions, filters or several `for` clauses
     in stack, symbolic lengths, generators in `stack`, tuple results.
   - Dependency note: `names.rs` counts every identifier token as a read, so
     targets over-approximate; lambda parameters are skipped as reads.

22. Scoped imports (`src/imports.rs`)
   - An import binds in the scope of its statement. A function-local
     `import os as k` changes `k` only in that function, so `k.reshape(...)`
     elsewhere keeps its meaning. A parameter, a local, a loop target, a lambda
     parameter, or a comprehension target that uses an imported name makes the
     name a value in that scope (the `SHADOWED` entry), so `torch.zeros` for a
     parameter `torch` is not a library call.
   - A function that both imports and assigns a name gives unknown in the full
     function. A function does not see an import of another function, because
     the read is a NameError at run time. A library name still classifies as in
     a file with no import. The last function import of a name wins. A nested
     `global` reads the module map, and `global k` makes a function import a
     module import.
   - A comprehension region covers the full node, so the first iterable also
     sees the comprehension names. The scan skips `string` and `type` nodes.
   - Module-level rebinding follows Python order (`Rebound`, `rebound_names`).
     With `import numpy as k` then `k = load()`, module code above the statement
     reads the import, and module code below it reads a value. A binding in a
     loop counts from the start of the outermost loop. `global k; k = load()`
     in a function counts from the `global` statement on, also if the function
     is never called.
   - A function body runs after the module code above it, so it reads the last
     map. A function called before the rebinding also reads unknown. A file
     that rebinds a tracked name pays for one region per top-level function or
     method. All these regions share one map.
   - `k = None` in an `except` clause keeps the import, for the idiom
     `try: import torch` / `except ImportError: torch = None`. If the clause
     runs, each use as a module raises, so no wrong shape can appear. It does
     not hide a class name, and any other `= None` counts. `k.seed = 1` and
     `k[0] = 1` also keep the import, so a monkeypatch of a module is not
     tracked. For a class, `P.x = 1` makes `P` opaque.
   - Unknown, not wrong: `np = None` plus `global np; import numpy as np` in a
     function; `k = 1` then `import numpy as k`; and a value rebinding with a
     second import of the name, read in a function. A module-level class or
     comprehension that binds a tracked name, above a rebinding of any tracked
     name, reads every rebound name as unknown, because regions store no places.
   - `file_backend` stays file-wide (`ImportScopes::file`).

Lazy call-site parameter seeding
--------------------------------
A call of a same-file function, closure, or method whose params are not all
annotated runs `apply_seeded_user_function`: it seeds the un-annotated params
from the argument shapes, replays the callee's assignments in a specialized
scope (`specialize_callee_call` → `process_assignment_item`), and traces the
return (`trace_specialized_return`: a name, `return <expr>`, or a tuple kept
element-wise for scan).
- Each specialization starts from the immutable `original_shapes`, so one call
  site never leaks into another. Only the first successful one writes back to
  the scope and `assignment_shapes` (hover and hints in the body).
- Re-entry gives `None`; depth ≤ 8 (`MAX_SPECIALIZATION_DEPTH`).
- `lax.scan`: param 0 from `init`, param 1 from `xs` without its leading axis;
  `ys` is return element 1 with that axis put back (`scan_body_ys_shape`).
- Scalar-typed params (`decay: float`) seed as rank 0.
  `FunctionShapeScope::all_params` holds every param (`param_order` only the
  annotated ones).

Known limitations / important caveats
-------------------------------------

- Server flow: `did_open` stores the text and analyzes it at once.
  `did_change` (INCREMENTAL sync) applies the ranged changes in message order
  and spawns a publish task. The task waits the debounce (`Pace`), runs one
  analysis per (uri, rev) from `DocState.committed`, and skips if a newer rev
  arrived. A stale request returns null. Only the analysis of the newest rev
  is committed. A memo is valid for one cache, one set of search roots, and
  one `max_depth`.
- Positions: the server chooses UTF-8 `positionEncoding` when the client
  offers it, else UTF-16. `LineIndex` converts tree-sitter bytes with the LSP
  line model.
- Diagnostics have the source `ndim-lsp` and a `code`: `shape-mismatch` or
  `shape-approximation`. `related` becomes related information.
- Hover answers only on a real name read or write (not an attribute name, a
  keyword argument name, an import, a decorator, or an annotation). A name
  bound in the scope of the cursor shows the shape of the assignment that
  holds there (`shape_at`); in a loop with a later binding it shows nothing.
- Dims of an annotation string: definition goes to the first site in the
  function scope; references and documentHighlight give every site;
  prepareRename and rename edit every site in the function and reject a name
  that is not a simple dim, changes a leading `_`, is used in a dim
  expression, or is already a dim of the function. The `.T` quick fix is
  offered only when the analyzer proves the rank-2 transpose fixes that
  mismatch. Edits are versioned when the client accepts `documentChanges`.
- `Settings` holds four options, read from `initializationOptions` and changed
  live by `workspace/didChangeConfiguration`: `diagnostic_severity` for
  `Mismatch` (default ERROR, any case), `approximation_severity` for
  `Approximation` (default WARNING), `inlay_hints` (default true), and
  `inlay_hints_max_length` (default 0, no limit). An invalid value gives the
  default. The value is under `ndim-lsp` or at the top level, and an absent
  key keeps its value. With no option in the value, a client with
  `workspace/configuration` gets a pull of section `ndim-lsp`; a reply is
  dropped if a newer notification arrived. A real change republishes the
  cached results and refreshes hints; no option changes an analysis. A
  publish holds the `settings` read lock until it sends.
- Import resolution searches the workspace roots (each with its `src` layout
  root), then site-packages found through `$VIRTUAL_ENV`, `$CONDA_PREFIX`, or
  `<workspace>/.venv` and `venv` (no Python call). Imports read the editor
  text of an open document (`Buffers`), else the disk. A buffer change, or an
  open or close whose text differs from the disk, calls `buffer_changed`: the cache entries
  that read the file are dropped, and the documents whose last analysis read
  it (all of them if an entry was dropped) get a new rev after their debounce.
  `commit` refuses a result whose reads are no longer current. `did_save` and
  watched `**/*.py` events drop the affected entries and analyze all open
  documents again. A workspace folder change clears the cache.
- `x.transpose(i, j)`, `x.max(...)`, and the methods of
  `torch_method_reading` are chosen per file from its imports
  (`file_backend`): torch only means torch, numpy/jax/flax/equinox/haiku/optax
  only means numpy, and no import or both means unknown unless both readings
  agree. `dim0`/`dim1` keywords always mean swap. The backend is not tracked
  per receiver.
- Subscript (`shape_of_subscript`): integer index drops the axis, slices
  (item 18b), `None` inserts, ellipsis expands. A list of integers gives its
  length to the axis. Every other index that is not a proven integer
  (`is_integer_expr`) makes the whole shape unknown.
- Multi-output tuple assignment (`tuple_rhs_shapes`) covers the explicitly
  modeled calls; other modes return `Ok(None)`.
- Symbolic-dimension comparison canonicalizes flat sums/products and literal
  factors (`d_state*2` equals `2*d_state`). `self.<attr>` is canonicalized to
  an identifier alias from `__init__`; layer constructor dims read it through
  `layer_at` instead.
- Higher-order functions: `vmap`, `equinox.filter_vmap`, `jax.lax.map`, and
  `jax.lax.scan` are modeled. `jit`, the `grad` family, and `pmap` are not.
- `LayerShapeAnalysis.layers` is a flat last-wins map kept for tests; the
  analysis resolves layers by scope (`extract_layer_assignments_scoped`).
- Approximations that remain: `jnp.select` takes the shape of the first
  choice; symbolic split points are taken as positive, ordered, and in bounds;
  `F.pad` and other rules give a dim no size (`?`) for a pad that is not an
  integer.

Rules added after `62e9ebd` (round three):
- The vmap path and the same-file binding path bind against `original_shapes`,
  never against the live shape of a parameter that the body assigns again.
- An imported function binds its arguments over the full signature
  (`resolve_imported_function_signature`, `bind_call_arguments`).
- The pieces of `split` and `chunk` must match the number of targets
  (`fit_pieces`). A symbolic `chunk` gives each piece the size `?`, except when
  a literal factor divides the size.
- `linspace`, `logspace`, and `geomspace` with array endpoints give
  `[num, *broadcast(start, stop)]`. `TorchLinspace` needs scalar endpoints.
- `x.sort()` has a shape only in a file that imports jax and no numpy or torch.
- `where` checks each pair of operands that has a shape.
- `tests/robustness.rs` analyzes truncated corpus files and asserts no panic.

Rules added after `29bfb64` (round four):
- `Float[Tensor, "..."]` and `Float[np.ndarray, "..."]` are array annotations
  (`contains_library_array`). The head must be a jaxtyping dtype, so
  `Union[Tensor, "Name"]` is no shape.
- `**`, `//`, `%`, `&`, `|`, and `^` broadcast and report like `+`
  (`BinaryOp::Elementwise`). A comparison of two operands broadcasts too, and
  a conflict there gives no shape and no report (`shape_of_comparison`).
- The method form `a.where(c, b)` uses the `where` rule.
- `self.<field>` resolves in the class of the method, then in its bases
  (`ShapeCtx::field_shape`). A class without the field gets no shape.
- A specialized callee with named annotations keeps only `Mismatch` errors
  from the seeded pass: its names and the dims of the call do not compare.
- `annotation_dimension_range` skips a name that a lambda or a comprehension
  binds.
- A size argument reads `*`, `//`, `+`, and `-` over integers, names from
  `x.shape`, and `self.<name>` (`scalar_dim_expr`): `x.view(b, t, self.heads,
  d // self.heads)`. A floor division is written `d//heads`.
- A `-1` in `reshape` is the input product over the known product
  (`infer_symbolic_minus_one`): equal factors cancel, integers fold, and a
  known dim that the input does not have stays as a divisor (`d//heads`). A
  divisor that is no plain name gives no shape. `x.size(i)` reads like
  `x.shape[i]` there.
- `x.shape[i]` and `x.size(i)` stand for the dim in a size expression
  (`shape_index_dim`), and `n = x.shape[0]` makes `n` a size name like
  `a, b = x.shape` does. `with_size_names` writes such a dim as `(dim,)`, so
  the dim is not read as a variable.
- A method call on a parenthesized expression or a subscript resolves its
  receiver first: `(x + y).sum(axis=-1)`, `x[0].reshape(-1)`.
- A name that holds a module of the file is called like a `self.<attr>`
  field (`name_module`, `shape_of_named_module_call`): `model = Enc(key)`
  with one binding, or a parameter `model: Enc` that the body does not bind
  again. `jax.vmap(model)(xs)` works too. A parameter has no constructor
  arguments, and its class must have no subclass in the file.
- A comprehension of modules of the file can read its loop variable:
  `[Block(64, k) for k in keys]`. That constructor argument then has no
  value, so a dim that needs it is unknown. A `key=` argument is not read at
  all, also for a framework layer.
- A method of a held module is called like the module: `self.enc.encode(xs)`
  and `model.encode(xs)` (`ShapeCtx::module_method`, `apply_submodule_scope`).
  Only an instance method of the file counts. A lookup of a name as a module
  comes after the import check, and `function_scope` finds a scope by its
  byte: a linear search there made a file with 30,000 functions too slow
  (`tests/lsp_debounce.rs` finds this).
- A binary operator error has its range on the expression of the statement.
  The related place is the annotation dim of the right operand, when both
  operands have an annotation site, else the right operand. With two sites
  the error goes through `push_error`, else through `report`.
- `find_binary_op_text` finds an operator with no space around it (`x**2`,
  `a@b`). Before, each such expression had no shape and no check.
- `@` takes a vector (`apply_matmul_shape`): a vector is a row on the left
  and a column on the right, and the result drops that axis. Two vectors
  give `[]`. A variadic vector gives no shape.
- An index that is an array of integers puts its shape in place of the axis:
  `x[i]`, `x[:, i]`, `np.eye(k)[labels]` (`is_integer_array`). Proven are
  `arange`, `argmin`, `argmax`, `argsort`, `randint`, `randperm`,
  `searchsorted`, an `Int[...]` parameter that the body does not bind again
  (`sole_typed_parameter`), an item of those, and a name with one such value.
  Arrays next to each other broadcast. A conflict, an integer or a list with
  an array, and arrays apart give no shape. All other arrays can be a mask.
- flax: a class field `dim: int` that no method writes makes `self.dim` the
  dim `dim` (`add_int_field_aliases`), like `self.dim = dim` in `__init__`.
- flax: `MultiHeadDotProductAttention`, `MultiHeadAttention`, and
  `SelfAttention` keep the shape of the query when `out_features` is absent.
- flax: `self.param(name, init, (sizes))` has the shape of the sizes (the
  `zeros` rule). `model.apply(variables, x)` runs `__call__(x)` when the
  class has no `apply` method. With `mutable=` or `method=` it has no shape.

Soundness fixes after the gap audit of 2026-11-10 (each one gave a false error
or a wrong shape before):
- A plain layer name follows Python scope and statement order
  (`ShapeCtx::local_layer`, `name_values`). A parameter or a local of a scope
  between hides an outer layer, and so does the body of a class that binds
  the name. A call uses the last binding before it. No layer is known for:
  two branches with different layers, a later binding in a loop around the
  call, a second binding of an outer name, and a name in a `global` or
  `nonlocal` statement. `model = model.to(device)`, `.eval()`, `.cuda()`,
  and `inference_mode(model)` keep the layer (`keeps_module`). Branches with
  the same layer, or with layers that all keep the shape, keep it.
- A `self` field with two different layers in one class has no layer
  (`self_attr_layer_at`), and so does a field that another value replaces
  (`self.fc = make_head()`). Layers that all keep the shape are the exception.
- `arange`: the step, `start=`/`stop=`/`end=`/`step=`, and float literals
  give `ceil((stop - start) / step)`, as numpy, jax, and torch do. A step
  next to a name gives no shape. `arange(n, 0)` gives no shape.
- `cumsum` and `cumprod` with no axis, and `sort` and `argsort` with
  `axis=None`, flatten (`apply_known_along_axis`). An axis that is a name can
  hold `None`, so it gives no shape.
- `KnownFunction::Fft`: `n=` or `s=` sets the length, so the call has no shape.
- `expand`, `expand_as`, and `broadcast_to` report an error when integer
  literals prove that the input does not broadcast (`refuse_broadcast`).
  `view_as` and `reshape_as` report two different element counts.
- A function with a transform decorator gives no shape and no check
  (`has_transform_decorator`): the names `vmap`, `grad`, `jacfwd`, ... as
  identifiers of the decorator (not in a string, not as the name of a keyword
  argument), and each decorator that is a function of the file.
- equinox `BatchNorm` and `SpectralNorm` give `(output, state)`. They are no
  array layers. `WeightNorm` stays transparent.
- `reshape` with `-1` gives no shape when a size argument is a variable with
  the name of an annotation dim and no proven dim (`infers_from_dim_name`).
  jaxtyping does not bind `n: int` to the dim `n`. A field (`self.heads`) is
  not such a variable.
- `d*2`, `d+d`, or `n+m` against `d` or `n` is a conflict (`exceeds` in
  `types.rs`), but only an `Approximation`: with a size of 1 the two
  broadcast. A dim with `**` is no flat sum.
- `2 * (d // 2)` as a size keeps its brackets (`scalar_dim_expr`).

Input sources (2026-11-11, each shape checked by `oracle/check.py`):
- `array`, `asarray`, `torch.tensor`, `torch.as_tensor` of a nested list or
  tuple give the shape of the literal (`literal_shape`): `[[1.0, 0.0], [0.0,
  1.0]]` is `[2, 2]`, a number is `[]`, `[]` is `[0]`. An item is a number
  (`is_number_text`), `x.shape[i]`, or a name with a known shape (`[v, v]`
  stacks). A ragged list, a star, a comprehension, an item that is not
  proven, and `ndmin=` give no shape.
- `KnownFunction::Sampler { at, numpy, spread }`: `jax.random.normal`,
  `uniform`, `randint`, `bernoulli`, `truncated_normal`, `gamma`, ... and
  `np.random.normal`, `uniform`, `randint`, `random`, `standard_normal`, ...
  give the shape of the size argument (position `at`, `shape=`, `size=`). A
  size is a tuple or list, `x.shape`, and for numpy one integer literal. A
  name goes through `with_size_names`, because a name can hold a tuple.
  `np.random.rand` and `randn` take the sizes one by one. With no size the
  result is `[]` only when each parameter of the distribution is a number.
- `zeros(x.shape)`, `ones(x.shape)`, `full(x.shape, v)` give the shape of `x`.
- `torch.randn_like`, `rand_like`, `randint_like`, `from_numpy` keep the shape.
- Not done: the keys (`jax.random.key`, `PRNGKey`, `split`), the methods of
  `np.random.default_rng()`, `jax.random.choice`/`permutation`/`categorical`.
- Effect on the real projects: shapes in noxton 419 to 611, equinox 87 to
  377, mujoco 585 to 905. One new diagnostic, and it is true: the warning at
  `noxton/functions/geometry.py:79`, where `q: Float[Array, "w x y z"]`
  (rank 4) meets `jnp.array([1, -1, -1, -1])`. The docstring says `(..., 4)`.

Test rule from the same audit: an expected shape in a test must come from the
real library, not from the belief of the author. Eight tests asserted a wrong
behavior as correct (`cumsum` without axis, `expand_as` to a wrong target,
equinox `BatchNorm` as one array). `NDIM_DUMP_SOURCES=<dir> cargo test --lib`
writes each source that a test analyzes (up to 20 kB) to `<dir>`. Do not put
a Python environment below `bench/` or `corpus/`: `incremental_tests` reads
all `.py` files there.

Outside-truth gate (`oracle/check.py`, a standing gate for each rule change):
  uv venv --python 3.12 oracle/.venv
  uv pip install --python oracle/.venv/bin/python numpy torch jax equinox flax jaxtyping einops optax
  NDIM_DUMP_SOURCES=/tmp/ndim-oracle/src cargo test --lib
  cargo build --release
  oracle/.venv/bin/python oracle/check.py /tmp/ndim-oracle/src
The script runs each source in the real libraries. Each function gets one
array for each jaxtyping parameter, with a different prime size for each dim
name. A shape of the tool must equal each shape the name had on that line,
and an error of the tool on a line that ran to its end is a false error. No
shape from the tool always passes. Required result: `shapes_wrong` 0 and
`errors_false` 0. `shapes_from_a_broken_annotation` counts tests whose function
breaks its own return annotation, which the tool trusts. Result of 2026-11-11
on the test sources: 7,028 shapes, 1,426 confirmed, 0 wrong, 275 errors, 0
false. The commit before the soundness fixes gives 15 wrong shapes and 5
false errors on the same sources. Limits: a method of a class is not called,
a function with a parameter that has no annotation is skipped, and a source
that needs a fake module does not run. `NDIM_LSP=<binary>` selects the binary.
Run it only on folders of plain probe files: it executes each file.

Real-code check (a standing gate): `cargo build --release`, then run
`target/release/ndim-lsp check .` inside real projects (the projects and the
result of 2026-11-10 are in "Current validation baseline"). Each error must be
true; read each one in the source. A false error found there comes before any
corpus or tracker work.

For a speed or incremental change also run the golden dump (byte-identical
with the baseline) and the stress benchmark (0 marker failures, 0 scenario
failures, no scenario slower than the 3 percent noise). Only a change of
analyzer behavior may change the golden dump; report each difference, then
replace the baseline file.

Coding conventions used so far
------------------------------

- Pure helpers in the library modules, table-driven tests.
- Simple string dimensions, no symbolic algebra engine.
- Unknown/dynamic information returns `Ok(None)`; a contradiction returns
  `Err(String)`, which becomes a `ShapeError`.
