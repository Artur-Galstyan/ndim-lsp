ndim-lsp LLM handoff
====================

Purpose
-------
ndim-lsp is a Rust/tower-lsp + tree-sitter-python project for static tensor shape analysis in Python code. The library modules under `src/` carry the analysis logic; `src/main.rs` is now wired end-to-end as an LSP server (diagnostics, hover, inlay hints, symbolic-dimension definition, and safe matmul fixes) on top of `analyze_layer_shapes`.

JAX compatibility audit
-----------------------

`bench/jax_compat/README.md` records the 0.9.2 -> 0.11.1 public-export audit,
its eight namespaces, source links, and conservative limits. This covers
recent additions, not all older or experimental JAX APIs. `audit.py` can
repeat the export comparison for the next release without installing JAX.

`src/known_functions/jax.rs` adds rules for all 26 new array functions in
those namespace differences. Existing stack/unbind rules are shared, and
the new byteswap method is shape-preserving. LAX top_k now honors axis.
Top-k and qr_multiply share validation between single-name and unpacked
calls, but only unpacking exposes their component tensor shapes.
Shape-changing options that are not static stay unknown.

`stack`, `concatenate`/`cat`, `vstack`, `hstack`, `dstack`, and `column_stack`
read each list/tuple element (including inline array expressions) as one
operand, instead of collapsing a homogeneous tuple into one operand. This
applies to JAX, NumPy, and PyTorch. A list comprehension over a provable array
is expanded to N copies of one element (N from 1 to 256, else unknown). A
sequence that is not a tuple, list, or such a comprehension (for example a
variable `xs` or a generator) makes the call unknown, because the shape
map does not represent container types. An element with an unknown shape
makes the whole call unknown. `block` with a tuple literal is unknown (NumPy
and JAX reject it); einops `rearrange`/`reduce`/`repeat` with a tuple of
tensors are unknown. `einops.pack` reads raw arguments and handles tuples.
An einops pattern with more than one `...` on a side is unknown (einops rejects
it).

End-to-end LSP stress benchmark
-------------------------------

`bench/generate_stress.py` writes `bench/stress/` deterministically (fixed seed):
a 22,323-line `stress_main.py`, five imported helper modules, and a 500-line
`paste_block.txt`. Regenerate with `python3 bench/generate_stress.py`.
`tests/lsp_stress.rs` spawns the built `ndim-lsp` binary, talks JSON-RPC over
stdio, and runs about 40 scenarios (including `typing_plain` and
`typing_with_inlay_requests`) (open, edits at line start/middle/end,
50-change burst, 500-line paste and delete, inserted errors, helper-file edits,
hover, definition, full inlay requests, edits after an idle pause, and a tiny
document).

Markers in the generated Python define the expected result and come from
operation semantics, never from analyzer output:
`# expected-error:`, `# expected-shape: a=[b, 4]`, `# stress-site: <name>`.

The tests are `#[ignore]`:

```sh
NDIM_STRESS_RUNS=3 NDIM_BENCH_OUT=/tmp/bench.json cargo test --release --test lsp_stress lsp_stress_benchmark -- --ignored --nocapture
NDIM_GOLDEN_OUT=/tmp/golden.json cargo test --release --test lsp_stress golden_dump -- --ignored --nocapture
```

- `NDIM_STRESS_RUNS` (default 5) sets the runs per scenario.
- `NDIM_BENCH_OUT` writes the JSON result. `NDIM_GOLDEN_OUT` writes the golden dump.
- Latency is total = debounce + server compute (from the server's
  `analysis: total=Nms` log) + other (transport and scheduling). The debounce
  column is the value the server chose for that edit, read from the
  `debounce=` field of the same log line: 150 ms while typing, 20 to 150 ms
  after an idle pause (see "Incremental analysis"), 0 for `didOpen`.
- A fast loop that sends each edit right after the previous publication counts
  as typing, so it gets 150 ms. The `floor_tiny_doc_change` scenario therefore
  waits (`settle(450)`) before each edit, to measure an edit after idle. The
  old 155 ms figure for it measured back-to-back edits, so it is not
  comparable.
- Peak RSS is sampled with `ps` every 25 ms, so it is a lower bound.
- The harness sends full text with no range, so it does not measure the saving
  of incremental sync transport.
- Do not benchmark with `NDIM_VERIFY_INCREMENTAL=1`: it adds a fresh parse and a
  fresh analysis to every edit.

Golden gate for refactors: `golden_dump` writes every diagnostic and inlay hint
of the stress project. Dump before and after a change, then `cmp` the two files.
A cleanup or a speed change must give a byte-identical dump. Do not fix
analyzer defects inside such a change, because the fix changes the dump.
`golden_has_no_internal_names` checks that no `__synth_` or `__ellipsis` name
reaches a message or a hint.

The harness checks about 13,800 expected markers (6,410 in `stress_main.py`,
6,637 in the paste payload, the rest in the helper modules). A `?` marker
(`# expected-shape: e=?`) says the name must have no shape: use it where
unknown is the true answer.

`lsp_stress_benchmark` passes: 0 marker failures and 0 scenario failures. It
asserts the expected markers and the scenario invariants. Do not loosen the
test to make it pass. A refactor must keep it green and keep the golden dump
byte-identical.

Closed targets (found by the benchmark, fixed in f63b9b8):

1. Inherited layer lost with a same-named self attribute: `self_attr_layer_at`
   now walks the class hierarchy (MRO) of the class that contains the call.
   An unresolved base before the defining class gives no shape. Bare `Module`,
   `object` and `ABC` bases are transparent. The lone-binding fallback is gone.
2. `torch.zeros`, `ones`, `empty` read the shape from varargs, a tuple or list,
   or `size=`. A single plain identifier gives `[n]`. A single arg with `.`, `(`
   or `[` gives unknown. `x.new_zeros`, `new_ones`, `new_empty` follow the same
   rule (`NewSizeConstructor`).
3. Burst debounce: `did_change` spawns one publish task per (uri, rev),
   single-flight. A superseded rev skips its work. A stale request returns null.
4. Inlay and other requests wait out the remaining debounce on a cache miss, so
   typing with inlay requests causes 1 analysis and 1 publication.
5. Stale cross-file state: `did_save` and dynamic `workspace/didChangeWatchedFiles`
   drop the affected cache entries, and all open documents are analyzed again.
   `ResolutionCache` entries carry stamps (mtime and size), failed lookups are
   cached, and an epoch revalidates once per analysis. A `parsed` text-keyed
   tree cache (up to 128 files, counter `parses`) avoids re-parsing imported
   files. `workspace/inlayHint/refresh` is sent if the client supports it.

Open limit: an unsaved helper buffer is still ignored (the server reads
imports from disk).

Incremental analysis
--------------------

An edit used to cost a full parse and a full analysis (about 260 ms on the
stress file). It now costs a reused parse and a replay of the unchanged parts.
The result must always equal a fresh analysis of the same text. Three layers:

1. Sync and parse (`src/sync.rs`, `src/incremental.rs`, `src/main.rs`).
   - The server advertises `TextDocumentSyncKind::INCREMENTAL`.
     `apply_changes` applies the ranged changes in order to the stored text
     (UTF-16 positions; lines end at `\n`, `\r\n`, or `\r`). A change without a
     range replaces the whole text.
   - `diff_edit` finds the one edit between the old and the new text (common
     prefix and suffix). `reparse` feeds it to tree-sitter with the old tree.
     If the old tree or the new tree has a syntax error, `reparse` parses from
     scratch, because tree-sitter recovers differently from errors with a
     reused tree. So the tree always equals a fresh parse, also after errors.
   - `parse_states` keeps, per URI, the text, tree, and memo of the last analysis
     that was committed. `commit` runs only for a successful result of the
     newest rev, so a stale or failed analysis changes nothing. `parse_states`
     is not cleared when a watched-file event clears `analysis_cache`: the tree
     base stays valid because the memo checks its disk dependencies itself.
2. Pre-pass memo (`UnitMemo`, `analyze_layer_shapes_with_memo`).
   - A "unit" is a top-level statement (every root child; an anonymous `;`
     is also a unit with an empty record). The pre-passes (`PrePass`: scopes,
     annotations, layer assignments, self-attribute layers, class summaries)
     are stored per unit in unit-relative positions
     (`SyntaxRecord`, `LayerRecord`), and shifted to the new positions with the
     `Shift` trait, `Delta`, and `Remap`.
   - A unit with the same text reuses its `SyntaxRecord`. A `LayerRecord` also
     needs the same import map (a digest of the whole import map, so an edit
     of any import line recomputes the layer records of all units) and valid
     disk dependencies (`ResolutionCache::record_deps`, `deps_valid`).
   - A unit with a syntax error is never reused, because its parse can depend
     on the text after it.
   - The first analysis of a text builds no memo, so opening a file is as fast as
     before. The first edit builds it (about 4 ms more than the plain
     pre-pass). A file over 4 MiB of text or 100,000 units gets no memo
     (`MAX_MEMO_TEXT`, `MAX_MEMO_UNITS`) and runs the plain path.
3. Propagation memo (`PropPlan`, `PropRecord`, `src/incremental/names.rs`).
   - `names.rs` finds the names each unit defines and reads and links units that
     share a name (a union-find over name hashes). The closure over-approximates:
     every identifier token counts as a read. Common names such as `__init__`
     and `forward` join most units into one hub group (567 of 858 units on
     `stress_main.py`), so an edit in a hub saves only part of the cost.
   - The plan marks the groups with a changed unit as dirty. Dirty groups run
     the propagate pass (`run_units`); clean groups replay their stored output
     (`Segment`s of errors, applications, assignment shapes, and the final scope
     shapes), shifted to the new positions. Statement-level groups need a
     `Remap` that finds a unit for every position. Loop bodies replay as part
     of their unit.
   - The plan falls back to a full run (`propagate_full`) when the dirty bytes
     exceed `MAX_DIRTY_SHARE` (0.6) of the file, a position has no unit, or two
     statements share a row. A fallback run records too, so later edits can
     replay.
   - The setup of the pass (function nodes, scope links, submodules,
     `original_shapes`, `ScopeIndex`) still runs over the whole file on any
     dirty edit (about 14 ms). It is not incremental.
   - Each dependency that an analysis feature adds must be visible to this
  model. The name test for a new binding reads only the function, or at
  module level the linked identifiers plus a digest of the global names and
  wildcard imports. A function that reads a module global joins the group of
  the global through the shared/reads edge of `names.rs` (a reader mentions
  the name, and a module write, a class body write, and a `global` statement
  all join one group), so no new edge type exists. The environment hash also
  holds the clash set (integer names that annotations use as dims). Module
  classes of other files record a probe dependency (`Deps` per probe, class
  source cache), and in-place changes of a field are found by name in the
  whole file. Comprehension and lambda bodies run inside their unit, and
  `sum`, `range`, `len` resolve through the unit's definitions, imports, and
  wildcard imports.
- `NDIM_NO_PROPAGATE_MEMO=1` is a kill switch: it turns layer 3 off and runs
     the whole-tree propagate pass (the pre-pass memo stays on).

`ResolutionCache` supports the memo with a per-path generation (a count of
`revalidate` marks), a clear count, and a cache id. `record_deps` records
which files a computation touched and `deps_valid` tells if they are unchanged.
A save that keeps mtime and size is seen only through the editor event path
(`revalidate` with the changed path), as the cache already works.

Verify mode. `NDIM_VERIFY_INCREMENTAL=1` (server environment) makes each edit
that has a base also do a fresh parse and a fresh analysis and compare them
(`first_tree_difference`, `first_analysis_difference`). On a difference the
server logs `incremental mismatch, used the fresh result: ...`, uses the fresh
result, and drops the memo. In `cfg!(test)` builds the same difference panics.
The cost is one extra fresh parse and analysis per edit, so never time with it.

Tests: `src/incremental_tests.rs` (47 library tests) and
`tests/incremental_edits.rs` (seeded random edit sequences over `corpus/` and
`bench/stress/`; after every edit the reparsed tree and the memo analysis must

Debounce and sync mode
----------------------

- `DEBOUNCE` in `src/main.rs` (150 ms) is the longest quiet time before a
  change is analyzed. `Pace` (`src/sync.rs`) keeps, per document, the time of
  the last change and a moving average (EWMA, alpha 0.5) of the wall time of
  recent analyses.
- A change within 400 ms of the previous one is typing and waits 150 ms. An
  isolated change (400 ms or more after the previous one) of a document with a
  known average waits `2 x average`, clamped to 20 ms through 150 ms. The first
  change after open waits 150 ms. `didOpen` does not wait.
- A cold run seeds the average. The first incremental run replaces it (no
  averaging with the cold cost). A fallback run and a failed run reset it. So does
  every re-analysis of the open documents (a root change, or a save or watched
  file event that dropped cache entries); the run after it is not sampled.
  After a reset the next edit waits 150 ms. A fast loop of edits right after each publication counts as typing.
- The first call after a change waits out the debounce of its rev. Hover, inlay,
  and other requests share that one analysis (single-flight per uri and rev,
  one analysis at a time per URI).
- Sync is INCREMENTAL. A position past the end of a line or of the text clamps to
  that end, as the LSP spec says. A position inside a surrogate pair, or a range that does not fit the stored
  text, drops the whole message and keeps the old text: the later changes are not applied to a text
  the editor does not have. The document is then out of sync (`in_sync` is
  false): it gets no analysis until a message with a full text arrives. The
  server publishes no diagnostics for it and answers inlay requests with null,
  and logs a warning. A stale version (older than the stored one) is ignored.

Limits of the incremental path
------------------------------

- Hub edits (`edit_init_layer`, `paste_500_lines`) save only part of the cost.
- A whole-file edit (`edit_char_start`) is a full run.
- An unsaved helper buffer is ignored (imports come from disk).
- Units with a syntax error are not reused.
- Module-global reads use the shared/reads edge, which over-approximates
  (every identifier token is a read), so a comprehension target joins the
  group of an equal global name. That costs reuse, never correctness.
- Replay clones the segments and the final scope shapes for the output. A clean
  group whose units did not move is shared by reference.

Rule for agents working on this repo
------------------------------------

**Verify before implementing.** `src/` is the source of truth; the roadmaps are summaries and may lag it. Before adding a known function, layer, or analysis feature, grep first:

```sh
grep -E "KnownFunction::|apply_known_" src/known_functions.rs
grep -E "LayerKind::|\"<ClassName>\"" src/layers.rs
grep -n "<feature_name>" src/analysis.rs src/main.rs
```

If the feature already exists, **stop and report that finding** — do not invent adjacent work (e.g. "I'll just add some more tests") to justify the run. Duplicate tests are net-negative: they grow the suite without growing coverage, and the next agent reading the suite will be misled about which paths are exercised.

When in doubt about a task's scope, look for the existing test module (every `apply_known_*` function has tests in the same file's `#[cfg(test)]` block) — if the cases your task description mentions are already covered there, the task is done.

What works now
--------------

1. Python import parsing
   - Supports plain imports, aliases, dotted imports, from-imports, relative imports, parenthesized/multiline imports, duplicate import last-wins.
   - Star imports are skipped.

2. Assigned call extraction
   - Finds simple assignment-call patterns like:
     - `layer = eqx.nn.Linear(...)`
     - `y = layer(x)`
   - Skips tuple unpacking, attribute assignment, bare calls, non-call assignments.

3. Import/call target resolution
   - `resolve_call_target` combines call target text with import map.
   - Example:
     - `import equinox as eqx`
     - `eqx.nn.Linear` -> `ResolvedTarget { parts: ["equinox", "nn", "Linear"] }`
   - Relative import dot count is preserved in `ResolvedTarget` when needed.

4. Module resolution on disk
   - `resolve_python_module_on_disk(module, search_roots)` checks:
     - `root/foo/bar.py`
     - `root/foo/bar/__init__.py`
   - No filesystem crawling. Deterministic path lookup.

5. Symbol/re-export following
   - `find_top_level_symbol` detects top-level class/function/import.
   - `resolve_implementation` follows import re-exports until class/function found, with max depth and cycle detection.

6. Callable signatures and call bindings
   - `extract_callable_signature` extracts:
     - top-level function params
     - class `__init__` params
   - `extract_call_arguments` gets positional/keyword call args.
   - `bind_call_arguments` maps args to param names and skips `self`/`cls` for class constructors.

7. Jaxtyping shape annotation extraction
   - `extract_jaxtyping_shapes` extracts function parameter shape strings like:
     - `x: Float[Array, "batch features"]`
   - Handles common wrappers and qualified `Array` forms.
   - Rejects f-strings/bytes strings and non-array string annotations.
   - Returns `Vec<FunctionShapeScope>`: index 0 is a module scope spanning the whole file, followed by one scope per `function_definition` (DFS order). Each scope carries `function_name`, `start_byte`, `end_byte`, and the per-function `shapes` map. Same-named params in different functions no longer collide.

8. Equinox Linear layer flow
   - Resolves and classifies `equinox.nn.Linear` through imports/re-exports.
   - Extracts layer assignments:
     - `layer = eqx.nn.Linear(3, 5)` -> `layer -> LayerKind::Linear { in_features: "3", out_features: "5" }`
   - Extracts layer applications:
     - `y = layer(x)` -> `LayerApplication`
   - Applies layer shape rules:
     - input last dim must match `in_features`
     - output last dim becomes `out_features`
   - `analyze_layer_shapes` orchestrates annotation extraction + layer extraction + propagation.

9. Known built-in function classification
   - `classify_known_function` recognizes many JAX NumPy, NumPy, Torch, and selected JAX LAX functions.
   - See `KnownFunction` enum and `TO_IMPLEMENT.md`.

10. Known built-in shape rules already implemented
   - `concatenate` / `cat`
   - `stack`
   - reductions: `sum`, `mean`, `max`, `min`, `prod`, `std`, `var`, plus `all`, `any`, `argmax`, `argmin`
   - `reshape`
   - `flatten`, `ravel`
   - `transpose`, `swapaxes`, `moveaxis`, `permute`
   - `expand_dims`, `squeeze`, `atleast_1d`, `atleast_2d`, `atleast_3d`
   - `broadcast_to`, `broadcast_arrays` / `broadcast_tensors`
   - `tile`, `repeat`
   - shape-preserving: `roll`, `flip`, `triu`, `tril`, `argsort`, `sort`, `cumsum`, `cumprod`, `array`, `asarray`, `*_like`
   - elementwise functions (`is_shape_preserving_call`): the one-operand ones
     (`exp`, `sqrt`, `abs`, `tanh`, ...) keep the shape. The two-operand ones
     (`maximum`, `minimum`, `fmax`, `fmin`, `add`, `multiply`, `power`,
     `arctan2`, `hypot`, `copysign`, the comparisons and logical functions in
     numpy, jax and torch: `torch.add`, `sub`, `mul`, `div`, `pow`, ...)
     broadcast both operands, and a Python scalar broadcasts against anything.
     A mismatch, a third positional argument, or an operand passed by keyword
     gives unknown. `torch.max` and `torch.min` have their own rule.
   - `clip` / `clamp` (`KnownFunction::Clamp`, free and method form): the input
     broadcasts with every array bound, so a larger `min` or `max` array makes
     the result larger. Bounds that are `None` or provable scalars are removed
     first. A bound with no known shape, or a mismatch, gives unknown.
   - `torch.bmm`: both operands rank 3, equal batch dim (a batch of 1 does not
     broadcast), equal contracted dim; result `[b, n, p]`.
   - `F.cross_entropy` / `F.nll_loss`: the class dim is axis 0 for an
     unbatched input and axis 1 otherwise. A target of the input's shape holds
     probabilities (`cross_entropy` only), a target without the class dim holds
     class indices. `reduction='none'` gives the input shape without the class
     dim, any other valid reduction a scalar. A `weight` must be rank 1 with
     one entry per class.
   - `where`
   - constructors: `zeros`, `ones`, `full`, `empty`, `arange`, `linspace`, `logspace`, `eye`, `identity`
   - diagonal/indexing basics: `diag`, `diagonal`, `trace`, `take`
   - linear algebra basics: `matmul`, `dot`, `jax.lax.dot`, `jax.lax.dot_general` approximated as matmul
   - stacking family: `vstack`, `hstack`, `dstack`, `column_stack`, `row_stack`
   - `pad`
   - `rot90`

11. Recursive shape evaluator (replaces flat query extraction)
   - `shape_of_expression` walks an assignment RHS bottom-up: `call`,
     `attribute`, `identifier`, `unary_operator`, `subscript`,
     `parenthesized_expression`, `binary_operator`, `tuple` (a shape only
     when all elements have the same shape).
   - Nested/chained calls in one expression now propagate, e.g.
     `jnp.exp(a @ b)`, `x.reshape(3,4).sum(axis=1)`,
     `jax.nn.softplus(jax.vmap(self.proj)(x))`.

12. `self.<field>` attribute access (issue #31)
   - Class fields with jaxtyping annotations (e.g.
     `A_log: Float[Array, "d_inner d_state"]`) are extracted into module
     scope; `shape_of_attribute` resolves `self.A_log`, including through
     chained methods like `self.A_log.astype(jnp.float32)`. A module-level
     write of the same name makes `self.<name>` unknown.

13. Tuple-pattern unpacking (issue #30)
   - `a, b = jnp.split(x, ...)` binds per-element shapes via
     `compute_split_shapes`; `L, _ = x.shape` binds each dim as a zero-rank
     scalar (`_` skipped). Handled in source order, interleaved with single
     assignments, by `handle_tuple_assignment` / `tuple_rhs_shapes`.
   - Tuple-literal right sides (`a, b = x, y`, `(a, b) = ...`, `[a, b] = ...`)
     bind element by element (`tuple_literal_shapes`). Every element is
     evaluated before any target is written, so `a, b = b, a` swaps and a
     rotation of three names works. A starred target (`first, *rest = ...`)
     takes its position; the starred name is always unknown (Python binds a
     list). A duplicate target keeps the last element. Differing lengths, a
     splat on the right, or two stars make every target unknown and evict
     stale bindings. An element error is reported once.
   - Unpacking a name (`a, b = x`) has two meanings. An array unpacks into its
     rows: a literal leading dim must equal the target count (else unknown), a
     symbolic leading dim is accepted, and each target gets the shape without
     the leading dim. A tuple carry (a
     `lax.scan` init tuple, a tuple literal bound to a name, a seeded carry
     parameter such as `final_mean, final_var = final_carry`) gives each
     target the one shared element shape, because only homogeneous carries are
     tracked. The analyzer tells them apart: `tuple_carries` holds the names
     whose current binding is a tuple carry, and any other name counts as an
     array only when `name_is_array` proves it (a non-scalar shape annotation,
     or every assignment to it in its scope is an array expression). A name
     that cannot be told apart gives unknown targets. Never guess a row shape
     for a tuple.
   - Control flow (`src/analysis/flow.rs`): `if`/`elif`/`else`, `match`,
     `try`, loops, and `with` run each arm from a snapshot of the entry state
     and join the live paths. A name with one shape on every live path keeps
     it, any other name is unknown. A name a loop body both reads and writes
     keeps its shape after the loop only if one pass leaves it unchanged
     (`x = f(x)`); otherwise it and every name written from it are unknown,
     and hints of the first iteration are taken back. Loop, `with`, and
     `except` targets, walrus names, `case` captures, `del`, `def`, `class`,
     and imports are binding events. Context managers that swallow errors
     are found by name (import aliases and the last name segment). Module
     scope does not count a `def` or `class` name as an earlier binding.
     Open: value statements (`return`, `assert`, bare calls) read the state
     at the end of the scope; hover shows the joined state; literal
     conditions are not folded; vmap bindings stay keyed by name.

14. vmap of attribute callables + inline vmap (issue #35)
   - `jax.vmap(self.layer)(x)` resolves `self.layer` to a layer built in
     `__init__` (`extract_self_attr_layers_by_class`) and applies it batched over the
     leading axis. `jax.vmap(f)(x)` inline form reuses `apply_vmap_call`.

14b. Direct self-attribute layer application
   - `self.fc(x)` / `jax.nn.relu(self.conv(x))` (no vmap) — the dominant
     forward-method style. `shape_of_call` resolves `self.<attr>` against
     `self_attr_layers` and applies the layer rule directly. Covered by
     `corpus/conv_net.py`.

14c. Symbolic factor cancellation in `split`
   - `Linear(d, 3*d)` then `split(qkv, 3)` cancels the literal factor so each
     chunk is `d`, not `split(d * 3, 3)` (`cancel_product_factor` in
     `known_functions.rs`). The fused-QKV pattern in `corpus/transformer_block.py`.

15. Per-assignment shape records for inlay hints (issue #28)
   - `LayerShapeAnalysis.assignment_shapes: Vec<AssignmentShape>` records the
     shape at *each* (non-annotated) assignment line, so a reassigned variable
     shows a hint per line. `compute_inlay_hints` reads this directly (no
     re-walk; `find_variable_line` removed).

16. Session-lifetime import-resolution cache (issue #36 / PR #38)
   - `ResolutionCache` keyed on `(import-path-segments, roots-fingerprint)` is
     shared across `analyze_layer_shapes` calls. Caches `ResolvedImplementation`
     in `map`, the extracted cross-file helper `FunctionShapeScope`s in
     `signatures`, and parsed trees in `parsed` (keyed by file text; `parses`
     counts real parses). Entries carry file stamps, failed lookups are cached,
     a changed file drops its entries, and the cache revalidates once per
     analysis (epoch). See `corpus`/cross-file integration tests.
   - For the memo each path has a generation (a count of `revalidate` marks, kept
     across `clear`), the cache has a clear count and an id, and
     `record_deps` / `deps_valid` tell if the files a computation touched are
     unchanged (see "Incremental analysis").

17. Closures read enclosing variables at call time
   - A closure that reads a variable of its enclosing function sees the shape
     the variable has when the closure is called, as Python does, not the shape
     at the definition. The body is evaluated at its own call, from inside the
     enclosing function or from another closure being evaluated there. Outside
     that, enclosing variables stay unknown (the whole-file pass evaluates a
     closure body at its definition).
   - Scope facts (`ScopeLinks`, lexical links between function scopes) cover only closures and
     the functions that enclose them. A name the closure binds itself
     (parameter, assignment, loop or `with` target, import, nested `def`,
     `global`) is local and shadows the enclosing one. A name that a nested
     closure rebinds with `nonlocal` is unknown. A call outside the enclosing
     function and a method closure through a class do not see function locals.
     A function reads a module global or integer constant when all writes come
     before the top-level statement of the reader and have one shape (a
     global that a class body also binds is unknown; constants must be one
     decimal literal or int-annotated; a function above the constant stays
     unknown). Integer constants resolve to the integer in call dims.
     Comprehension and lambda bodies read the live shapes of the scope where
     they stand (see item 21). Fully annotated closures read
     the call-time value too, and a mismatch with it is a true error, reported
     once.

18. User submodules (`self.<attr> = Block(...)`)
   - A field built from a class of the same file is a user module. Calling it
     (`self.blk(x)`, `Block(features=64)(x)`, `jax.vmap(self.blk)(x)`) runs
     the module's `__call__` (it wins) or `forward`, found through the class
     MRO, on the argument shapes. The constructor arguments give the
     `self.<attr>` fields and the parameters of `__init__` (or dataclass-style
     fields) their values, so two call sites of one class get their own shapes.
     A vmapped module peels and restores the batch dim.
   - It stays unknown when the field is written with anything but one
     constructor call of one class of the file, when a class between the field
     and the method rebinds a field the method reads, when a base before the
     method is unresolved, and past the depth bound (recursion terminates).
     A same-named function never replaces an unresolved field.
   - Classes imported from other files run through a probe (depth 2, never
     for site-packages or library roots). Constructor arguments reach it only
     as literals, plain names, or simple arithmetic. Errors show at the call.
     Fields that are `nn.ModuleList`, `nn.Sequential`, a list of modules, or a
     comprehension of modules, indexing, and chain loops (`x = layer(x)` as
     the only body statement) are tracked; a repeat count that is not literal
     is known only if one application keeps the input shape. Any in-place
     change of a field (by attribute name in the file) makes it unknown, so
     `self.layers.append(...)` in a loop stays unknown. Modules in locals,
     `zip`, `reversed`, slices, and `ModuleDict` stay unknown. A class defined
     twice in one namespace makes its calls unknown. Loss layers (`MSELoss`,
     `L1Loss`, `SmoothL1Loss`, `HuberLoss`, `BCELoss`, `BCEWithLogitsLoss`,
     `CrossEntropyLoss`, `NLLLoss`) check input and target and apply the
     reduction; `weight` and similar options are not read.
   - Annotated callee parameters are checked against the argument shapes: a
     rank mismatch or an integer mismatch is a true error; a named dim against
     an integer annotation, and a variadic annotation, are not errors.

19. Scalar operands in binary operations
   - A binary-op operand is a provable scalar (`2`, `math.sqrt(k)`, `len`,
     `float`, `int`, `x.shape[<integer>]`, a numpy or jax elementwise function
     of scalars, a name only ever bound to scalars, arithmetic on those, or a
     scalar-typed parameter) or an array with a resolved shape. A scalar
     broadcasts against any array. An operand that is neither stays unknown,
     because it could be an array that broadcasts. The check is flow-insensitive
     on purpose (`name_is_scalar`), so a reassignment in a loop or branch cannot
     make an earlier read wrong.

20. Internal names never reach the output
   - The evaluator binds inline operands to synthetic names (`__synth_N`, text
     kept in `synthetic_text`) and uses `__ellipsis` internally. A shape with a
     dimension that holds an internal name is not stored. In error messages
     `scrub_internal_names` puts the source text back; an error whose message
     cannot be restored is dropped, because a garbled message is worse than
     none. Names unpacked from `x.shape` (`a, b, c = x.shape`) stand for their
     dims (`scalar_dims`), so `reshape(a * b, c)` shows real dims, and the
     name stops standing for a dim when it is rebound.
   - `golden_has_no_internal_names` and `internal_name_scan_detects_a_leak` in
     `tests/lsp_stress.rs` check the rule over the stress project.

21. Comprehensions and lambdas (`src/analysis/inner.rs`)
   - A body is evaluated once, where its result is used: a list comprehension
     in `stack`/`concatenate`, `sum` over a comprehension or generator, a
     lambda given to `vmap`, `lax.map`, or `lax.scan`, and a direct lambda
     call. The `Frame` binds the loop variable or parameter to the shapes of
     one iteration. Iterating needs a provable array. A dim spelled with the
     loop variable becomes unknown. A scan lambda with a tuple carry binds it
     unknown. Names a body binds are masked, so an outer name never leaks in.
   - Not evaluated: `ys = [f(x) for x in xs]` kept in a name, a lambda stored
     in a name, set and dict comprehensions, filters or several `for` clauses
     in stack, symbolic lengths, generators in `stack`, tuple results.
   - Dependency note: `names.rs` counts every identifier token as a read, so
     targets over-approximate; lambda parameters are skipped as reads.

Lazy call-site parameter seeding (the architecture extension)
-------------------------------------------------------------
The former single-pass limit is fixed. When a call resolves to a same-file
function/closure/method whose params are not all annotated,
`apply_seeded_user_function` (src/analysis.rs) seeds the un-annotated params
from the caller's resolved argument shapes and lazily replays the callee's
own assignments in an EPHEMERAL specialized scope (`specialize_callee_call`
→ shared `process_assignment_item`), then derives the return shape via
`trace_specialized_return` (bare identifier, general `return <expr>`, and
tuple returns kept element-wise for scan). Key invariants:
- Multi-call-site soundness: specialization always starts from an immutable
  `original_shapes` snapshot; one call site's shapes never leak into
  another's. First successful specialization (only) writes back to the
  global scope + assignment_shapes so hover/inlay light up in the body.
- Recursion guard: active-specialization stack, re-entry → None, depth ≤ 8
  (`MAX_SPECIALIZATION_DEPTH`).
- `lax.scan` bodies: param0 seeded from init (incl. tuple carries), param1
  from xs minus its leading axis; `ys` = body return elem 1 with xs' leading
  dim prepended (`scan_body_ys_shape`).
- Plain-scalar-typed params (`decay: float`) seed as rank-0 and broadcast
  like literals in elementwise ops.
- `FunctionShapeScope::all_params` holds every declared param (`param_order`
  holds only annotated ones).

Known limitations / important caveats
-------------------------------------

- `src/main.rs` is wired end-to-end: `publish_diagnostics_for` gets the
  analysis of the newest text and publishes `ShapeError`s as LSP diagnostics;
  `on_hover` renders shape strings (markdown `MarkupContent` with a fenced
  python block); inlay hints are emitted. `did_open` stores the text and
  analyzes it at once. `did_change` (INCREMENTAL sync) applies the ranged
  changes to the stored text and version in message order, and spawns a
  publish task. The task waits the debounce chosen for that rev (20 to 150 ms,
  `Pace`), runs one analysis per (uri, rev) from the `parse_states` base, and
  skips if a newer rev arrived. A stale request returns null. Only the
  analysis of the newest rev is committed. The first analysis after open parses and
  analyzes in full; later ones reuse the tree and the memo (a memo is valid
  for one cache, one set of search roots, and one `max_depth`; another value
  drops it) (see "Incremental analysis" and "Debounce and sync mode"). The
  server advertises UTF-16 `position_encoding` and converts every tree-sitter
  range by byte offset to UTF-16 LSP positions.
- LSP also advertises `textDocument/definition` and quick-fix code actions.
  Go-to-definition takes a simple symbolic dimension token to its first
  annotation occurrence in the same function scope. A matmul diagnostic offers
  “Append `.T` to the right operand” only when the analyzer proves a rank-2
  transpose resolves that exact mismatch; the edit is UTF-16-safe and
  document-versioned.
- Diagnostic severity is independently configurable, case-insensitively, via
  `initializationOptions.diagnostic_severity` for `Mismatch` errors (default
  `ERROR`) and `initializationOptions.approximation_severity` for
  `Approximation` errors (default `WARNING`).
- Import resolution searches the workspace roots, then site-packages found
  through `$VIRTUAL_ENV`, `$CONDA_PREFIX`, or `<workspace>/.venv` and `venv`
  (no Python call). The resolution cache is keyed by (path, name) and checks file
  stamps. `did_save` and watched `**/*.py` events (dynamic registration) drop
  the affected entries and analyze all open documents again. A workspace folder
  change clears the cache. These events clear `analysis_cache` and give every open
  document a new rev, but keep `parse_states`: the memo checks its own disk
  dependencies. The server has no configuration handler.
  Severity options are read only in `initialize`, so a change needs a restart.
- Shape maps are now scoped per function. `extract_jaxtyping_shapes` returns `Vec<FunctionShapeScope>` (a module-level scope followed by one per `function_definition`), and `analyze_layer_shapes` routes each call to the smallest containing scope. `scope_for_byte` / `scope_index_for_byte` break size ties by preferring the later-pushed (inner) scope.
- Method calls like `x.reshape(...)`, `x.sum(...)`, `x.transpose(...)`,
  `x.astype(...)`, `x.to(...)`, `x.repeat(...)`, and `x.expand(...)` are wired
  end-to-end. `x.transpose(i, j)` is a torch two-axis swap but a numpy/jax
  axes permutation, so the rule is chosen per file from its imports
  (`file_backend`): torch only means swap, numpy/jax/flax/equinox/haiku/optax only means
  permutation, and no import or both means unknown unless both readings agree.
  `dim0`/`dim1` keywords always mean swap. `x.max(y)` and `x.max(dim)` follow the same per-file choice;
  `torch.max(a, b)` broadcasts and `torch.max(x, dim)` (a tuple result) is
  unknown. The backend is not tracked per receiver. `torch.flatten` and
  `x.flatten(start_dim, end_dim)` honor the dims (a positional argument that is
  not a string counts as torch); out-of-range dims are unknown.
- Nested/chained calls in one expression (`jnp.sum(jnp.flatten(x))`, `x.reshape(...).sum(...)`) now propagate via the recursive `shape_of_expression` evaluator — this replaced the flat `extract_calls`-based extraction.
- Subscript/indexing is implemented (`shape_of_subscript`): integer-index axis drop, slices (numeric `a:b` and `:n` folded; others approximated by the original axis), `None`/newaxis insert, ellipsis expansion, trailing implicit full slices. Advanced/boolean array indexing is approximated as a single axis drop.
- Multi-output tuple assignment covers `split`, default `meshgrid`, default
  linalg `svd`/`qr`/`eig`, top-k-style functions, supported RNN/LSTM/GRU
  layers, and other explicitly modeled calls in `tuple_rhs_shapes`. Its
  approximations and unsupported modes intentionally return `Ok(None)`.
- Symbolic-dimension comparison canonicalizes flat commutative sums/products
  and literal factors, so `d_state*2` equals `2*d_state`. `self.<attr>` is
  canonicalized to an identifier alias from `__init__` before storage, and the
  alias lookup is class-scoped. Limitations: aliases still need an
  identifier RHS; layer constructor arguments have the `self.` token stripped
  (for example, `Linear(self.d_inner, ...)`) but do not go through the alias
  map, so a differently named attribute is not mapped; and subtraction, division,
  and arbitrary parenthesized expressions are not generally normalized.
- `apply_matmul_shape` broadcasts batch dims numpy-style (align right; missing or literal-`1` dims broadcast, otherwise exact symbolic match required), so `(b, n, d) @ (d, k)` → `(b, n, k)`.
- Higher-order functions: `vmap` is modeled (free/inline/attribute, named
  callables and lambdas); `jax.lax.map` and `jax.lax.scan` (same-file body or
  lambda) are modeled. `jit`, the
  `grad` family, and `pmap` are not.
- Current known-function shape rules are pragmatic string-based rules. They do not do full symbolic algebra.
- Some shape rules are approximate by design. Example: `jax.lax.dot_general` currently maps to `Matmul` semantics.
- Layer assignments are tracked with their defining byte position via `extract_layer_assignments_scoped` (returns `Vec<LayerAssignment>`). At call time, `analyze_layer_shapes` picks the innermost function-scoped layer whose enclosing scope contains the call site. The flat `LayerShapeAnalysis.layers` HashMap is preserved (last-wins) for backward compatibility with existing tests, but resolution no longer uses it.
- `ShapeError` has `variable`, `message`, a tree-sitter `Range`, kind,
  optional related-information location, and optional `ShapeFix`; `main.rs`
  converts its ranges to UTF-16 LSP ranges.

How to continue
---------------

Always validate with:

```sh
cargo test --quiet
cargo clippy --all-targets --all-features
```

Clippy is fully clean (including `src/main.rs`); keep it that way.

For a speed or incremental change also run the golden dump (byte-identical
with the baseline) and the stress benchmark (0 marker failures, 0 scenario
failures, no scenario slower than the 3 percent noise). See "End-to-end LSP
stress benchmark". Only a change of analyzer behavior may change the golden
dump; report each difference, then replace the baseline file.

Recommended next implementation steps
-------------------------------------

**The exhaustive tracker pass is done.** Every catalog entry that fits the
current array-shape model has classification, a rule, and tests. The remaining
❌ entries in `TO_IMPLEMENT.md` need a richer model: wrapped-function semantics
(`jit`, the `grad` family, `pmap`), branch-output unification
(`lax.cond`/`lax.switch`), device-mesh state, plain non-array values
(`broadcast_shapes` and the `ps` argument to `einops.unpack`), or an arbitrary
callable (`equinox.nn.Lambda`). Treat the tracker, not this paragraph, as the
authoritative detailed list.

**Prioritize by the coverage harness, not by gut.** Run
`cargo test corpus_coverage_report -- --nocapture`, read the ranked dark spots,
and implement the top one. Grow `corpus/*.py` so the ranking stays
representative. Current open targets, in impact order:

1. Add a representative corpus model only when it exercises a behavior absent
   from the current 24 files; run the coverage report first and work from an
   actual dark spot rather than increasing the file count.

2. If corpus evidence warrants a richer architecture, choose one coherent
   extension: user-helper tuple returns, branch-output unification for
   `lax.cond`, or tracking a narrowly scoped non-array literal value. Do not implement a low-value
   tracker row in isolation.

3. Improve expression precision where it affects real code: map
   `self.`-prefixed layer constructor arguments through the alias map for
   differently named attributes, and extend symbolic normalization beyond the supported flat
   sum/product forms.

4. Expand LSP presentation only after the underlying analysis proves the
   information is correct (for example, richer related-information or inlay
   tooltips).

5. Keep `TO_IMPLEMENT.md` and `README.md` honest
   - When a function is classified, mark Classified ✅.
   - When a real shape rule exists, mark Shape rule ✅.
   - When tests exist for that shape rule, mark Tests ✅.
   - Flip the matching `README.md` checkbox in the same PR — drift between docs and code wastes future agent runs.

Coding conventions used so far
------------------------------

- Prefer pure helpers in `lib.rs` modules and heavy unit tests.
- Do not wire into LSP until pure behavior is well tested.
- Favor simple string dimensions over a symbolic algebra engine for now.
- Unknown/dynamic information usually returns `Ok(None)` instead of error.
- Actual contradiction/mismatch returns `Err(String)` or `ShapeError` at higher orchestration levels.
- Tests are intentionally extensive and mostly table/macro driven for known-function coverage.
